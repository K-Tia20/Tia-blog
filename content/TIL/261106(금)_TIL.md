# 저장 불러오기 로딩 화면과 월드 파티션 전환 계획

## 1. 저장 데이터를 읽기 전에 로딩 화면을 띄웠다

이어하기는 저장 슬롯을 조회하고 데이터를 복원한 다음에야 로딩 화면을 열었다. 맵을 여는 작업도 게임 스레드를 멈추게 해서, 같은 프레임에 화면을 만들면 사용자가 보기 전에 로딩이 시작될 수 있었다.

`ICGameFlowSubsystem::ShowLoadingThen`에서 로딩 UI를 먼저 열고, 화면이 그려질 프레임을 확보한 다음 저장 조회·복원이나 맵 이동을 시작하도록 순서를 바꿨다.

| 조작 | 변경 후 흐름 |
| --- | --- |
| 타이틀에서 이어하기 | 클릭 → 로딩 화면 → 최신 유효 슬롯 조회·복원 → 오픈월드 |
| 타이틀의 저장 목록에서 불러오기 | 선택한 슬롯의 불러오기 클릭 → 로딩 화면 → 해당 슬롯 복원 |
| 게임 중 저장 목록에서 불러오기 | 확인 → 로딩 화면 → 현재 맵에서 저장 상태 복원 |

이어할 데이터가 없거나 읽기에 실패하면 이전 화면으로 돌아가 안내를 표시한다. 인게임 불러오기는 현재 진행을 덮을 수 있어 확인 단계를 유지했다.

## 2. 프롤로그 이후 오픈월드를 보여주는 조건을 추가했다

`ICLoadingWidget`에서 월드 액터 초기화, 진행 중인 서브레벨 로딩과 표시 요청, 캐릭터 첫 애니메이션 자세를 확인한다. 첫 자세가 잡히면 복원된 카메라를 갱신하고 몇 프레임을 더 기다린다. 첫 화면의 텍스처 등 렌더링 자원도 준비할 시간을 주되, 이 추가 대기는 최대 **3초**로 제한했다. 준비가 끝나면 새 게임은 기존 페이드로 월드를 보여준다.

## 3. 월드 파티션은 맵과 NPC 배치 확정 뒤에 검증한다

`L_OpenWorld`를 읽어 보니 World Partition이 비어 있었고, `NPCAnchor`와 `L_SmartObject`는 항상 로드되는 서브레벨이었다. 배치를 마친 뒤 **원본 맵을 보존하고 `_WP` 시험 맵에서 전환을 검증**하기로 했다.

- **NPC**는 로드된 앵커와 생활 오브젝트에 의존한다. 구역을 나갔다 돌아왔을 때 다시 생성되고 일과가 이어지는지 확인한다.
- **퀘스트 안내**는 로드된 목표나 앵커를 찾아 NavMesh 경로를 계산한다. 멀리 있는 목표의 위치를 유지하고, 가까워졌을 때 안내선이 이어지는지 확인한다.
- **워프·이어하기**는 멀리 있는 목적지나 저장 위치의 셀과 바닥 충돌을 먼저 준비해야 한다. 워프 4곳과 기존 저장 파일을 검증 대상으로 잡았다.

팀 공유용 `Docs/World/World_Partition_Plan.ko.md`에 전환 순서와 확인 항목을 적고, `AGENTS.md`에서 팀원의 AI도 찾을 수 있게 연결했다. [Epic 월드 파티션 변환 문서](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine)

## 4. NPC와 플레이어 외형 교체 위치를 확인했다

NPC는 `DT_IC_NPC`의 대상 행에서 메시·애니메이션 프로필·초상화를 연결한다. 플레이어는 `DT_IC_PlayerPreset`의 `PRESET_PLAYER_M/F`를 먼저 읽는다. 기존 캐릭터의 ID를 유지하고 외형 항목만 바꾸면 대사·퀘스트·스킬 연결을 이어갈 수 있다.

색상 변경은 재질에서 시작할 수 있다. 새 VRoid 모델은 한 명으로 먼저 시험하고 뼈 구조와 애니메이션, 무기 위치, 눈·입 표정, 머리카락 물리와 실내외 조명을 확인할 예정이다.
