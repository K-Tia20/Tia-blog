# Meshy 헤어를 MetaHuman Groom으로 만들기

오늘은 **허리까지 오는 웨이브에 얇은 앞머리와 얼굴 옆머리**가 있는 플레이어용 헤어를 만들었다. Meshy에서 생성한 메시의 형태를 참고해 Blender에서 모발 곡선을 제작하고, Unreal Engine **5.8.4**의 MetaHuman 플레이어에 Groom으로 연결했다.

여성 Ada와 남성 Bo에는 각각 피팅본을 만들었다. 게임의 외형 편집 화면에서 **허리 웨이브 · 시스루뱅**을 선택하고, 기존 길이·색·거칠기 조절을 사용할 수 있는 첫 번째 제작본이다. MetaHuman과 Mutable을 연결한 전날 작업은 [[261108(일)_TIL]]에 정리했다.

## 오늘 구현한 헤어 선택 화면

기존 게임의 시작 화면과 캐릭터 생성·HUD 흐름에 헤어를 추가했다. 별도의 캐릭터 제작 프로그램을 만든 작업은 아니다. 플레이 중에는 `Tab`으로 외형 편집을 열고 **헤어** 탭에서 선택한다.

게임 카탈로그에는 같은 스타일의 여성용·남성용 피팅을 별도 데이터로 등록했다. 화면에는 현재 프리셋과 호환되는 항목만 표시한다. 기존 추가 헤어 8종에 새 스타일이 더해져 **프리셋별로 9종**을 사용할 수 있다. 기본 헤어와 헤어 없음은 별도 선택이다.

![[20261109-waist-wave-creator.png]]

실제 게임 창에서 새 카드의 선택 표시와 썸네일을 확인했다. 자동 회전 버튼도 눌러 캐릭터가 회전하는 것을 확인했다. 외형은 사용자가 **외형 저장하고 시작**을 눌러 저장하며, 검사용 선택값을 기존 사용자 저장 파일에 덮어쓰지는 않았다.

## 참고 이미지와 Meshy 생성 기록

먼저 제작 방향을 정할 참고 이미지를 준비했다. 아래 이미지는 **AI로 만든 디자인 참고 이미지**이며, 게임에서 렌더링한 결과가 아니다. 얇은 앞머리, 얼굴 양옆을 따라 내려오는 모발, 긴 S자 웨이브가 기준이다.

![[20261109-waist-wave-reference.png]]

Meshy 공식 MCP 서버를 사용하는 프로젝트 연결로 이미지 기반 3D 생성을 한 번 실행했다. 이번 헤어 작업의 사용량은 **35크레딧**이다. 이후 피팅과 곡선 수정은 로컬에서 진행했다.

다음 비교 이미지의 왼쪽은 디자인 참고, 가운데는 **Meshy가 생성한 실제 메시의 Blender 화면**, 오른쪽은 **언리얼에서 렌더링한 최종 Groom**이다. 가운데 모델에 헤어 가닥을 자동으로 추가한 결과가 아니라, 그 형태를 참고해 곡선을 별도로 제작한 과정이다.

## 폴리곤 메시에서 모발 곡선으로 제작하기

Meshy 원본에는 머리카락의 덩어리 형태가 있지만, 이번에 필요한 두피 부착용 뿌리 정보와 모발 가이드 구성이 그대로 들어 있지는 않았다. 원본을 보존한 뒤 실제 Ada 얼굴·몸 기준 모델을 Blender로 가져와 크기와 위치를 맞췄다.

원본 메시의 외곽을 **48개 방향과 64개 높이**에서 샘플링하고, 웨이브 덩어리의 가이드와 그 주변의 모발 곡선을 작성했다. 앞머리와 얼굴 옆머리는 별도로 배치했다. 두피에 투영한 뿌리에는 UV를 기록하고, 가닥 끝으로 갈수록 폭이 줄어들게 했다.

| 그룹 | 렌더 모발 수 | 가이드 수 | 물리 설정 |
| --- | ---: | ---: | --- |
| MainWaves | 64,000 | 1,600 | 활성화 |
| WispyBangs | 1,440 | 120 | 고정 |
| FaceFraming | 1,960 | 140 | 활성화 |
| Flyaways | 900 | 90 | 활성화 |
| 합계 | **68,300** | **1,950** | 동적 그룹 3개 |

곡선마다 점 64개를 사용했다. 렌더 모발은 화면에 보이는 가닥이고, 가이드는 여러 모발의 움직임을 이끄는 곡선이다. 두 수를 더해 렌더 모발 수라고 부르지 않도록 구분했다.

앞머리는 이번 버전에서 정적으로 두었다. 눈 근처의 모발이 시뮬레이션 중 눈을 침범하는 문제를 줄이기 위한 선택이다. VRoid 모델이나 헤어 데이터를 가져와 사용한 작업은 아니다.

## Groom 가져오기 경로 수정

처음 시험한 Blender Hair Curves의 Alembic 경로에서는 설치된 UE 5.8 임포터가 곡선 knot 정보를 처리하는 과정에서 오류가 발생했다. 이 문제는 과거의 GPU 멈춤과 별개인 **CPU 임포트 오류**로 기록했다.

일반 POLY 곡선의 Alembic은 지오메트리 백업으로 남기고, 실제 게임용 에셋은 프로젝트의 에디터 모듈에 만든 `QueenGroomEditorLibrary`로 가져왔다.

```text
Blender 편집용 곡선
  → .qgroom 곡선 데이터
  → 프로젝트 에디터 브리지
  → Unreal HairDescription
  → Groom 에셋과 MetaHuman 바인딩
```

`.qgroom`은 이 프로젝트에서 가닥 좌표·폭·뿌리 UV·가이드·그룹을 보존하는 파일 형식이다. 일반 Alembic 표준 형식으로 부르는 것은 정확하지 않다. 가져오기 코드는 헤더, 그룹 수, 파일 범위, 좌표와 폭을 검사하고 기존 에셋을 교체하지 않도록 했다.

Epic 엔진 소스를 수정하지 않고 프로젝트의 에디터 모듈에서 처리했다. 새 리비전은 새 패키지 경로로 가져오며, 일반 Reimport 버튼만으로 이 제작 과정을 재현하지는 않는다.

## 남녀 피팅과 눈 주변 수정

눈꼬리 옆에서 수평으로 튀어나오던 모발은 옆머리 가이드의 시작 위치와 곡선을 조정했다. 앞머리, 옆머리, 정수리와 뒤통수는 정면·측면·후면·얼굴 근접 화면으로 확인했다.

여성용 곡선을 남성 얼굴에 바인딩했을 때에는 등과 어깨 쪽 의상이 뒷머리를 뚫고 나왔다. 얼굴 바인딩이 연결됐다는 사실만으로 몸 전체 피팅이 맞는 것은 아니었다.

남성용은 두피의 뿌리와 UV를 유지하면서 어깨 뒤쪽 곡선을 바깥으로 보정했다. 보정량만 줄이면 옷 관통이 다시 나타났기 때문에, 여유를 주기 시작하는 높이도 함께 조정했다. 최종 정지 자세에서는 이전에 보이던 큰 의상 침범이 사라졌고, 뒷머리가 어깨에서 떨어지는 볼륨은 남아 있다.

![[20261109-waist-wave-six-views.png]]

여성 얼굴 근접 화면이다. 눈 주변과 얇은 앞머리를 확인한 실제 엔진 캡처다.

![[20261109-waist-wave-female-closeup.png]]

남성용도 같은 이름의 헤어지만 별도 Groom과 바인딩을 사용한다.

![[20261109-waist-wave-male-closeup.png]]

## 기존 헤어로 바꿀 때 충돌 설정 복원하기

긴 머리에는 프리셋별 몸 충돌용 Physics Asset을 연결했다. 실행 검사에서 새 헤어를 선택했다가 기존 헤어로 바꾸면, 새 헤어의 충돌 설정이 남는 문제가 나타났다.

처음에는 덮어쓰기 전 값을 한 번만 저장하고 복원하도록 바꿨다. 다시 검사하니 원래 값이 `nullptr`인 경우가 실패했다. 설치된 엔진의 `UGroomComponent::SetPhysicsAsset`은 다음 조건 때문에 빈 값을 전달하면 아무 작업도 하지 않았다.

```cpp
if (InPhysicsAsset && PhysicsAsset != InPhysicsAsset)
```

값이 있는 원래 에셋은 setter로 복원하고, 원래 값이 비어 있으면 컴포넌트를 재등록하는 범위 안에서 포인터를 비우도록 했다. 이때 Niagara 시뮬레이션과 충돌 정보도 다시 준비한다.

```cpp
FComponentReregisterContext Reregister(Component);
Component->PhysicsAsset = nullptr;
```

Mutable의 완료 알림이 반복될 때 선택한 추가 헤어가 프리셋의 기본 헤어 캐시에 저장되는 경로도 막았다. 수정 뒤에는 기존 헤어와 기본 헤어 복원, 체형 변경 후 새 헤어 유지, 남녀 전환을 다시 검사했다.

## WBP 카드와 세 언어 연결

기존 `WBP_QueenCharacterCreator`와 `WBP_QueenAppearancePartCard`를 사용했다. 새 헤어는 카탈로그 데이터와 실물 썸네일로 추가했다. 같은 이름의 남녀 피팅 카드가 동시에 나타났던 문제는 `IsHairAvailable`을 확인해 호환 카드만 만드는 방식으로 수정했다.

표시 이름은 기존 중앙 번역 구조에 넣었다.

```text
GameStrings.json
  → ST_Game 문자열 테이블
  → WBP가 표시하는 FText
  → Unreal Gather / Import / Compile
  → 문화권별 Game.locres
```

두 피팅본은 `Hair.Hair_Queen_WaistWaveWispy.Label` 키 하나를 공유한다.

| 언어 | 표시 이름 |
| --- | --- |
| 한국어 | 허리 웨이브 · 시스루뱅 |
| 영어 | Waist waves · wispy bangs |
| 중국어 간체 | 及腰波浪 · 空气刘海 |

기존 349키·1,047번역에 키 하나를 더해 **350키·1,050번역**이 됐다. 실제 남녀 WBP 카드 6가지 조합에서 번역, 썸네일, 선택 핸들러와 선택 표시를 확인했다.

## 이동과 점프 중 헤어 확인

실제 테스트 맵에서 새 헤어를 착용한 플레이어를 이동시키고 점프시켰다. 공개 게임 API로 입력을 전달한 검사이며, 키보드 조작을 촬영했다고 기록하지 않았다.

관찰된 수평 이동은 약 **274.41cm**, 점프 높이 증가는 약 **115.56cm**다. 긴 머리·얼굴 옆머리·잔머리의 Niagara 그룹 3개가 활성화된 상태도 확인했다.

![[20261109-waist-wave-move-jump.gif]]

GIF는 실제 뷰포트에서 시간 간격을 두고 캡처한 **13프레임**을 연결했다. 연속 화면 녹화는 아니며, 원본 비율을 유지해 축소했다. 프레임을 생성하거나 모발 형태를 이미지에서 보정하지 않았다.

첫 촬영에서는 프레임 지연 때문에 점프 시작과 해제가 같은 콜백에서 실행돼 점프가 기록되지 않았다. 게임의 점프 기능을 바꾼 것이 아니라, 실제 점프 요청 시점부터 유지 시간을 계산하도록 촬영 코드를 고친 뒤 다시 관찰했다.

## 남은 다듬기와 배운 점

현재 결과는 게임에 연결한 첫 제작본이다. 모발 덩어리와 정수리 가르마는 더 다듬을 수 있고, 남성 뒷머리는 어깨 관통을 피하도록 여유를 둔 형태다. 모든 체형 극단값·의상·격한 동작에서 관통이 없다고 판정한 상태는 아니다.

앞머리 물리는 꺼져 있다. LOD는 스트랜드 밀도 조절을 사용하며, 별도의 헤어 카드 LOD와 패키징한 게임의 성능 검사는 후속 작업이다. 길이 조절도 기존 Groom을 **35~100% 범위에서 자르는 기능**이며 웨이브 모양을 새로 생성하는 기능은 아니다.

오늘 가장 크게 배운 것은 **AI가 만든 메시의 외형, 게임용 모발 데이터, 캐릭터에 맞는 피팅을 각각 확인해야 한다는 점**이다. 바인딩 성공과 실제 착용 결과도 별개였다. 화면에서 눈·어깨·등을 보고, 실행 검사로 교체·복원·저장까지 확인해야 문제를 찾을 수 있었다.
