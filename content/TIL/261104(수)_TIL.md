# VRoid 표정 애니메이션과 검 일반공격 슬래시 VFX 구현

오늘은 VRoid에서 가져온 캐릭터에 **눈깜빡임과 대사에 따른 입 움직임**을 추가했다. 이어서 검 일반공격 VFX를 현재 콤보 애니메이션에 맞추고, 보유한 Free Magic 슬래시를 단순한 흰색·하늘색 잔상으로 수정했다.

표정은 캐릭터가 가진 모프 타깃을 재사용하고, 슬래시는 실제 검날의 위치와 움직임을 기준으로 배치했다. 두 작업 모두 기존 몸 애니메이션과 전투 판정을 유지하면서 표현을 추가하는 방식으로 진행했다.

## 오늘 한 일

| 대상 | 적용한 동작 |
| --- | --- |
| 플레이어 남녀 프리셋 | 눈깜빡임만 적용 |
| NPC 11명 | 대기·이동·파티·대화 중 눈깜빡임, 본인 대사에 따른 입 움직임 |
| 검 일반공격 | 3단 콤보의 총 5회 베기에 슬래시 생성, 검날 방향·길이 추적 |

## 1. VRoid 모프 타깃으로 표정을 움직였다

캐릭터마다 얼굴 애니메이션을 새로 만들기 전에, 가져온 스켈레탈 메시의 모프 타깃부터 확인했다. 이번 모델들에는 눈을 감는 모프와 모음별 입 모양이 이미 들어 있었다.

```text
눈 감기: Fcl_EYE_Close
입 모양: Fcl_MTH_A / Fcl_MTH_I / Fcl_MTH_U / Fcl_MTH_E / Fcl_MTH_O
```

`UICFacialAnimationComponent`에서 필요한 모프가 있는지 확인하고, `SetMorphTarget()`으로 가중치를 조절하도록 구성했다. 통합 눈 감기 모프가 없으면 좌우 눈 감기 모프를 찾아 사용한다. NPC만 발화 기능을 활성화하므로 플레이어에게는 대사가 전달돼도 입 모양을 쓰지 않는다.

### 눈깜빡임은 세 구간으로 나눴다

눈 감기 0.055초, 유지 0.025초, 뜨기 0.10초로 구성했다. 눈을 감고 뜨는 가중치는 부드럽게 바꾸고, 반복 간격은 캐릭터별로 2.5~5.5초 사이에서 무작위로 정한다. 초기 대기 시간은 1~3초다.

저프레임에서는 한 프레임의 시간이 깜빡임 전체 길이보다 길어질 수 있다. 이때 시간을 그대로 더하면 눈이 감긴 상태를 한 번도 표시하지 못할 수 있어서, **깜빡임 한 프레임의 진행량을 제한**했다. 8·30·60·120 FPS 조건에서 눈이 실제로 감기는지 검사했다.

잠들거나 전투불능 상태가 되면 이 컴포넌트의 깜빡임과 발화를 중지한다. 메시나 프리셋이 바뀌면 이전 표정 값을 정리하고 새 메시의 모프를 다시 연결한다.

### 모프 값을 쓴 뒤 실제 메시 평가 결과도 확인했다

몸 애니메이션과 VRM 후처리 그래프가 있는 상태에서는 컴포넌트 내부의 값만 확인해서는 부족했다. 얼굴 컴포넌트가 메시 평가보다 먼저 실행되도록 Tick 의존성을 연결하고, 애니메이션 평가 뒤에도 입 모프가 실제 렌더링 가중치에 남는지 검사했다.

## 2. 대사 텍스트의 모음을 입 모양 5개에 연결했다

현재 입 움직임은 **텍스트 기반의 간이 립싱크**다. 대사 문자열을 읽어 각 글자의 모음을 구하고, 가까운 A·I·U·E·O 입 모양에 연결한다.

완성형 한글은 다음 계산으로 중성 인덱스를 구해 매핑 테이블을 조회한다.

```cpp
const uint32 Code = uint32(Character);
const int32 MedialIndex = ((Code - 0xAC00) / 28) % 21;
const int32 MouthIndex = HangulMouth[MedialIndex];
```

이 계산은 코드에서 완성형 한글 범위를 확인한 뒤에 수행한다. 독립된 모음 자모와 영문 모음도 별도로 처리한다.

| 입 모양 | 현재 연결한 한글 모음 |
| --- | --- |
| A | ㅏ, ㅑ, ㅘ |
| I | ㅣ, ㅟ, ㅢ |
| U | ㅜ, ㅠ, ㅡ |
| E | ㅐ, ㅒ, ㅔ, ㅖ, ㅙ, ㅚ, ㅞ |
| O | ㅓ, ㅕ, ㅗ, ㅛ, ㅝ |

예를 들어 **안녕하세요**는 `안(A) → 녕(O) → 하(A) → 세(E) → 요(O)` 순서다. 21개 모음을 입 모양 5개로 근사하므로 실제 발음을 완전히 재현하지는 않는다.

글자마다 입 모양과 시작·종료 시간을 가진 발화 큐를 만든다.

| 구간 | 기본 시간 |
| --- | --- |
| 일반 글자 | 0.14초 |
| 공백 | 0.065초 |
| 쉼표·세미콜론·콜론 | 0.18초 |
| 나머지 문장부호 등 입 모양이 없는 글자 | 0.28초 |

입 벌림은 최대 0.65를 목표로 하고, 각 큐 안에서 열렸다 닫히는 곡선을 적용했다. 모음 사이도 가중치를 보간해 바꾸며, 공백과 문장부호에서는 입을 닫는다.

이 구현은 실제 음성을 분석하지 않는다. 받침·자음별 입술 닫힘이나 음성의 길이·억양까지 맞추려면 별도의 음성 타이밍 정보가 필요하다.

### 말하는 NPC와 대화 종료 처리가 중요했다

대화 위젯의 `SetSpokenLine()`에서 표시할 문장과 화자 ID를 전달한다. 얼굴 컴포넌트는 **자기 NPC의 ID와 화자가 일치할 때만** 입을 움직인다. 화자가 없는 플레이어·나레이션 문장이나 다른 NPC의 대사에는 반응하지 않는다.

문장이 끝나면 입을 닫고 선택지를 기다리는 동안 반복하지 않는다. 선택지·선물 화면으로 전환하거나 대화를 닫을 때, 대화 상대가 바뀔 때도 발화를 정리한다.

메뉴가 열리면서 메시 Tick이 멈추면 마지막으로 벌어진 입이 남을 수 있었다. `StopDialogue()`에서 모프를 0으로 만드는 것에 더해, 필요한 경우 메시 평가와 렌더 데이터 갱신까지 수행해 닫힌 입을 바로 반영하도록 했다.

## 3. 검 일반공격의 타격 시점과 슬래시 위치를 맞췄다

기존 검 VFX는 타격 원뿔의 반경과 단계별 기울기로 그린 고정된 호와 바닥 표시였다. 공격이 실행되는 시점에는 생성됐지만, 실제 검날의 위치·길이·휘두르는 방향을 따라가는 구조는 아니었다.

먼저 현재 남녀 검 몽타주의 타격 이벤트를 확인했다. **3단 콤보지만 베기는 총 5번**이었다.

| 콤보 단계 | 베기 수 | 몽타주상의 타격 시점 |
| --- | --- | --- |
| 1단 | 1회 | 0.15초 |
| 2단 | 2회 | 0.15초, 0.45초 |
| 3단 | 2회 | 약 0.183초, 0.733초 |

위 시간은 몽타주 재생 위치 기준이며, 실제 경과 시간은 공격속도의 영향을 받는다. 기존 타격 이벤트가 발생할 때마다 슬래시를 생성하도록 유지하고, 생성된 효과가 검날을 따라가게 바꿨다.

### 검날의 두 점으로 위치와 방향을 계산했다

`AICWeaponActor::GetBladeTrace()`에서 칼날 시작점과 끝점을 얻는다. 시작점을 효과의 원점으로 삼고, 두 점의 차이로 검날 방향을 구한다. 이전 프레임의 검 끝 이동량에서 검날 방향 성분을 제외하면 휘두르는 방향을 구할 수 있다.

```text
효과 원점 = 칼날 시작점
X축 = normalize(검 끝 - 칼날 시작점)
Y축 = 검 끝 이동량을 X축에 수직인 평면에 투영한 방향
효과 회전 = MakeFromXY(X축, Y축)
효과 배율 = 실제 칼날 길이 / 원본 슬래시 외곽 반경 100cm
```

메시 평가 뒤의 자세를 읽도록 효과를 `TG_PostUpdateWork`에서 갱신하고, 메시 Tick을 선행 조건으로 연결했다. 첫 생성 프레임에는 이전 소켓 자세를 복원해 정방향·역방향 베기의 초기 방향을 잡는다.

잔상은 1·2단에서 0.14초, 3단에서 0.15초를 기준으로 하며 공격속도로 나눠 적용한다. 공격 ID가 바뀌거나 장착 무기가 바뀌면 남아 있는 슬래시를 제거한다.

## 4. 보유한 슬래시를 일반공격용으로 단순화했다

Free Magic의 `NS_Free_Magic_Slash`를 복제하고, 기존 `SM_Free_Magic_Slash1` 메시를 재사용했다. 복사본은 **단일 메시 파티클을 한 번 생성하는 구성**으로 줄였다.

머티리얼은 Unlit·Translucent·Two Sided로 만들었다. 초승달의 일부 구간만 남기고 양끝의 폭을 줄여 뾰족하게 만들었다. 흰 중심과 하늘색 가장자리를 사용하고, 짧게 나타났다 사라지도록 알파를 조절했다.

| 새 에셋 | 위치와 역할 |
| --- | --- |
| `NS_IC_NormalSwordSlash` | `IsekaiClass/VFX/CombatEffect/NormalAttack/Sword`의 일반공격용 Niagara |
| `M_IC_NormalSwordSlash` | 같은 폴더의 슬래시 윤곽·색·투명도 머티리얼 |

`DT_IC_CombatVFX`의 전체 27개 행 중 `NORMAL_SWORD_1~3`만 수정했다. 이 세 행은 `bFollowWeaponSwing=True`로 검날 추적을 켜고 바닥 범위 표시와 레거시 대체 효과를 껐다. 원본 VFX와 몽타주, 데미지·충돌·타격 시간 데이터는 유지했다.

![[20261104-sword-normal-slash.png]]

남녀 캐릭터의 2단 두 번째 베기에서 캡처한 슬래시 부분이다.

## 5. 셰이더 오류와 캡처 문제를 해결했다

### Niagara CPU VM에서 페이드 수식을 바꿨다

커스텀 HLSL에 쓴 `smoothstep()`이 이번 Niagara CPU VM 컴파일에서 지원되지 않아 실패했다. 0~1로 제한한 값에 같은 형태의 3차 보간식을 직접 적용했다.

```hlsl
float tail = saturate((t - 0.35) / 0.65);
float fadeOut = 1.0 - tail * tail * (3.0 - 2.0 * tail);
```

머티리얼에서 사용할 수 있는 함수라도 Niagara의 CPU 실행 경로에서 그대로 컴파일되는지 확인해야 했다.

### 버텍스 좌표는 보간해서 픽셀 셰이더로 전달했다

슬래시 윤곽 계산에 `PreSkinnedPosition`을 바로 연결했더니 픽셀 셰이더에서 사용할 수 없다는 컴파일 오류가 났고, 게임에서는 기본 머티리얼이 표시됐다.

`PreSkinnedPosition → VertexInterpolator → 윤곽 계산`으로 바꿔 버텍스 단계의 위치를 픽셀 단계로 전달했다. **파티클이 생성됐다는 것과 의도한 머티리얼로 보인다는 것은 별도로 확인해야 했다.**

### 짧은 효과는 저프레임 캡처에서 놓칠 수 있었다

0.14초 정도의 슬래시는 몇 프레임 뒤에 캡처하면 이미 사라질 수 있었다. 검증 세션에서는 모션 블러를 끄고 고정 시간 간격과 슬로모션을 사용했으며, 첫 활성화의 머티리얼·PSO 컴파일 경로를 예열한 뒤 남녀 콤보를 다시 촬영했다.

## 검증 결과와 남은 확인 사항

표정 관련 자동 검사 4개와 일반공격 관련 검사 6개가 통과했다. 화면 검증에서는 플레이어 남녀와 NPC 11명의 표정을 확인했고, 검 콤보는 남녀 각각 5회씩 총 10개 타격 캡처를 확인했다.

- 표정: 모프 존재와 실제 변형 데이터, 저프레임 깜빡임, 대화 위젯 연결, 화자 구분, 발화 종료 시 입 닫힘
- 일반공격: 콤보 애니메이션, 데미지와 타격 창, 기존 원거리 공격, 검날 위치·길이 추적, 2배 공격속도에서의 잔상 시간, 공격 취소 시 제거
- 데이터: 원본 백업과 CSV를 비교해 검 일반공격 3개 행만 변경됐는지 확인

검증 중 테스트 레벨에서 VRAM 초과 경고가 보였고, 최종 캡처 뒤 에디터 종료 단계에서는 비정상 종료 코드 `-1073741819`가 남았다. 캡처와 기능 검사는 완료됐지만, 이 결과로 성능이나 종료 안정성까지 검증됐다고 보지는 않는다. 두 현상의 원인은 별도로 확인해야 한다.

## 배운 점

**표정의 모양과 실행 조건을 나눠야 재사용하기 쉽다.** 모델에 이미 있는 모프를 공통 컴포넌트로 제어하면서, 누가 말하는지와 언제 멈추는지는 대화 흐름에서 결정하도록 구성했다. 모프 값이 바뀌는 것뿐 아니라 실제 메시 평가 뒤의 결과도 확인해야 했다.

**VFX가 나오는 시점과 공간에서 움직이는 기준도 따로 봐야 한다.** 타격 이벤트에 효과를 연결했더라도 고정된 원뿔 모양이면 현재 검 애니메이션과 어긋날 수 있다. 이번에는 타격 이벤트로 생성 시점을 맞추고, 실제 검날로 위치·회전·크기를 맞췄다.

또한 컴파일 통과, 파티클 생성, 화면 표현, 성능은 각각 다른 확인 항목이었다. 자동 검사와 실제 캡처를 함께 사용해야 기본 머티리얼 대체나 짧은 효과의 캡처 누락까지 발견할 수 있었다.
