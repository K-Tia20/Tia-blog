# VRoid에 갑옷을 입혀 더퀸 NPC10 만들기

VRoid 기본 캐릭터에 갑옷을 맞추고 **더퀸의 새 NPC10**으로 연결했다. 디자인 이미지를 확인한 뒤 Meshy로 3D를 만들고, Blender에서 체형과 리깅을 보정했다. 추가로 애니풍 표현을 맞추고 다음 캐릭터에 재사용할 공용 프리셋을 만들었다.

## 언리얼 적용 결과

![[20261110-npc10-result.png]]

캐릭터와 갑옷이 실제 빛과 그림자를 받도록 수정했다. 원본 VRM과 Meshy 모델은 보존했다.

## 대기 걷기 달리기

![[20261110-npc10-locomotion.gif]]

대기 → 걷기 → 달리기 순서의 실제 언리얼 클립 캡처. 기존 로컬 애니메이션을 VRoid 뼈대에 맞췄다. 테스트 맵에서는 속도에 따라 자동 전환하고 두 지점 사이를 이동한다.

## 디자인에서 투구 수정까지

![[20261110-npc10-concept.png]]

위 이미지는 승인한 **AI 디자인 참고 이미지**다. 단단한 은색 갑옷과 관절 사이 검은 패딩, 가운데가 갈라지지 않는 앞뒤 보호판을 기준으로 잡았다.

![[20261110-npc10-blink.gif]]

생성된 투구가 얼굴과 겹쳐 투구·바이저·목 보호대를 직접 다시 만들었다. 고개 좌우 60도, 상하 25도 등의 검사 자세에서 얼굴·투구·금속 목 보호대의 표면 교차가 없었다. 어깨·무릎·장갑 가중치와 다리를 들 때의 보호판 변형도 보정했다.

## 피부와 입술 보정 전후

![[20261110-npc10-skin-before-after-v11.png]]

왼쪽은 수정 전, 오른쪽은 수정 후다. 같은 조명·카메라의 실제 언리얼 캡처를 같은 범위로 확대했다. 위 전신 화면과 동작 GIF는 이 피부 보정 전의 기록이다.

- **원인:** NPC에 이전의 밝은 피부 재질 오버라이드가 남아 있었고, 원본 입술색도 옅었다.
- **수정:** 오래된 오버라이드를 제거하고 Default Lit에서 피부 밝기 배율을 `0.7 → 0.45`로 맞췄다. 따뜻한 피부색과 입술 대비를 보완하고 검토 맵의 노출도 통일했다.
- **확인:** 재실행과 새 블루프린트 인스턴스에서 적용을 확인했다. 원본 VRM·텍스처는 보존했고 추가 Meshy 크레딧은 0이다.

## 애니풍 표현과 공용 프리셋 만들기

기존 NPC10을 기준으로 원신·명조 방향의 애니풍 기본 표현을 맞췄다. 이번에는 얼굴색과 갑옷을 한 캐릭터에만 보정하는 데서 더 나아가, **공용 마스터 재질과 캐릭터별 프리셋**으로 나눠 다음 캐릭터에도 적용할 수 있게 만들었다.

![[20261110-npc10-anime-result.png]]

위 화면은 이번 수정까지 적용한 실제 언리얼 결과다. 앞부분의 전신 화면과 동작 GIF는 이전 작업 단계의 기록이다.

### 얼굴과 눈 표현 전후 비교

![[20261110-npc10-anime-face-before-after.png]]

왼쪽은 이전 피부 보정까지 적용한 모습이고, 오른쪽은 공용 애니풍 재질을 적용한 모습이다. 같은 카메라와 스튜디오 조명에서 비교했다.

얼굴의 잘게 나뉘는 음영을 줄이고 머리 방향에 맞춰 법선을 보정했다. 법선은 표면이 어느 방향을 향하는지 나타내는 값으로, 이를 조정해 코와 볼의 명암이 지나치게 거칠게 보이는 부분을 정리했다. 피부색·그림자색·입술색은 따로 조절할 수 있게 했다.

눈썹과 속눈썹의 색·알파 기준을 정리하고, 눈의 복잡한 반짝임은 단순한 공용 하이라이트로 바꿨다. 눈·속눈썹·입 내부의 작은 자기 그림자는 끄고, 얼굴·투구·갑옷의 그림자는 유지했다.

### 갑옷 반사와 질감 전후 비교

![[20261110-npc10-anime-armor-before-after.png]]

기존 갑옷은 강한 금속 반사와 세밀한 요철이 얼굴의 애니풍 표현과 섞여 보였다. 노멀 맵 강도와 텍스처 대비를 낮추고 금속성·거칠기·명암 경계·하이라이트를 공용 재질의 파라미터로 조절했다. 차가운 은색과 남색 계열의 그림자로 색감을 맞췄다.

갑옷과 투구는 같은 공용 표면 재질을 사용하고, 검은 패딩은 반사와 하이라이트를 줄인 별도 인스턴스로 구분했다. 새 장비에서도 같은 마스터 재질에 텍스처와 값을 넣어 표현을 맞출 수 있다.

### 햇빛 방향과 조명이 바뀔 때

![[20261110-npc10-anime-sun-directions.png]]

조명 방향은 캐릭터별 컴포넌트가 전달하고, 얼굴 방향은 머리뼈를 기준으로 갱신한다. 태양이나 고개가 움직일 때 얼굴 명암이 같은 방향에 붙어 있지 않도록 했다.

![[20261110-npc10-anime-lights-off.png]]

왼쪽은 직접 조명을 끄고 약한 스카이라이트만 유지한 상태이고, 오른쪽은 모든 조명을 끈 상태다. 피부·눈·갑옷 표면은 **Default Lit**을 사용하고 **Emissive를 0**으로 설정해 실제 조명의 영향을 받게 했다. 얇은 윤곽선은 별도의 메시와 재질로 그린다.

### 표정과 걷기 달리기 확인

![[20261110-npc10-anime-expressions.png]]

기존 표정과 갑옷 보정 모프 **58개**를 보존했다. 눈 감기와 입 모양을 확인하고, 윤곽선 메시에도 얼굴 변형을 전달해 표정과 테두리가 따로 움직이지 않도록 했다.

![[20261110-npc10-anime-walk-run.png]]

위 두 장은 걷기·달리기 클립의 정지 프레임이다. 실제 실행 검사에서는 **대기·걷기·달리기 전환**, 순찰 6구간, 눈 깜빡임 5회를 확인했다. 재질을 바꾸면서 기존 이동·표정 기능이 유지되는지도 함께 검사했다.

### 다음 캐릭터에 재사용하는 구조

![[20261110-npc10-anime-reuse.png]]

왼쪽은 색상을 바꾼 일반 Character Blueprint이고, 오른쪽은 NPC10이다. 같은 메시를 사용하는 두 Blueprint에 공용 마스터 재질을 연결하고 캐릭터별 프리셋으로 색을 달리했다. 색상값은 각 캐릭터의 독립된 동적 재질 인스턴스에 보관한다.

| 공용 요소 | 역할 |
| --- | --- |
| `M_AnimeFace` | 피부와 눈 등 얼굴 재질의 색·입술·명암·법선 보정 |
| `M_AnimeSurface` | 갑옷 등 표면의 색·요철·반사·하이라이트 제어 |
| `M_AnimeOutline` | 얇은 윤곽선 표현 |
| `AnimeCharacterBase` | 새 캐릭터가 공용 외형 시스템을 사용할 수 있는 기본 클래스 |
| `AnimeVisualComponent` | 캐릭터별 재질 연결과 머리·조명 방향 갱신 |
| 캐릭터 프리셋과 JSON | 재질 슬롯 이름·텍스처·색상·머리 축 등 캐릭터별 설정 |

공용 에셋은 `/Game/TheQueen/Characters/Common/Anime`에 모았다. NPC10 설정은 `DA_NPC10_Anime`에 두고, 재질 슬롯은 번호 대신 **이름으로 연결**했다. 새로 생성한 NPC10 인스턴스와 에디터를 다시 연 상태에서도 적용을 확인했다.

다음 캐릭터는 아래 순서로 적용한다.

1. 스켈레탈 메시를 가져오고 Blueprint의 Mesh에 지정한다.
2. 공용 기본 클래스를 사용하거나 기존 Blueprint에 외형 컴포넌트를 연결한다.
3. 설정 템플릿을 복사해 실제 슬롯 이름과 텍스처를 넣고 `face`·`detail`·`surface` 역할을 지정한다.
4. `Apply-AnimeStyle.ps1`로 캐릭터별 재질 인스턴스와 프리셋을 만들고 Blueprint에 적용한다.
5. 조명·고개 회전·표정·걷기·달리기를 확인하고 저장 후 다시 열어 점검한다.

**공용화한 범위는 재질·조명 제어·윤곽선·프리셋·적용 도구다.** 얼굴 UV가 다르면 입술 마스크와 명암 위치를 조정하고, 다른 체형의 갑옷은 피팅·관절 가중치를 확인해야 한다. 다른 뼈대의 애니메이션은 리타기팅이 필요하다. 윤곽선은 추가 메시를 그리므로 NPC 수가 늘면 렌더링 비용도 확인한다.

이번 애니풍 수정은 기존 모델을 로컬에서 보정해 **추가 Meshy 크레딧 0**으로 진행했다. 새로운 Meshy 생성은 디자인 이미지를 먼저 확인한 뒤 진행하기로 했다.

## 오늘 배운 점

- AI로 만든 3D도 캐릭터 체형과 뼈대에 맞추는 과정이 필요하다.
- 자체 발광을 낮추는 것과 실제 빛을 받게 만드는 것은 다르다. 얼굴은 Default Lit에서 피부색·입술 대비를 보정하고, 눈은 원본 색·알파를 유지했다.
- FBX 재임포트 뒤 회색으로 보인 문제는 재질 슬롯 번호가 어긋난 탓이었다. 슬롯 이름과 번호를 함께 복구했다.
- 다른 캐릭터에도 재사용할 수 있지만, 체형이 다르면 다시 피팅해야 한다. 공용 장비로 분리하는 작업은 아직 별도다.
- 공용 마스터 재질과 캐릭터별 프리셋을 나누면 다음 캐릭터의 색·질감을 같은 기준으로 맞출 수 있다.

Meshy 최초 생성은 **15크레딧**, 이후 로컬 수정은 **추가 0크레딧**. 확인 맵은 `/Game/TheQueen/NPC10/L_NPC10Test`다.


## 갑옷 파츠 분리와 리깅 보강

NPC10의 승인된 은색 갑옷 디자인을 유지하면서, 철판이 옷처럼 휘거나 애니풍에서 물렁하게 보이는 부분을 보강했다. 투구, 넓은 허리와 하체, 겹치는 장갑 구성은 유지하고 **단단한 판과 부드러운 안감을 구분**했다. Meshy 재생성 없이 로컬에서 수정했다.

![[20261110-npc10-armor-v13-before-after.png]]

### 형태를 먼저 확인하고 파츠 나누기

![[20261110-npc10-armor-v13-clay.png]]

재질을 끈 상태에서 실루엣과 면을 확인했다. 원본에는 떨어진 조각도 있었지만, 가슴과 일부 팔 장갑, 허벅지와 정강이처럼 움직임이 다른 부위가 이어진 부분도 있었다. 관절 경계를 정확히 잘라 분리하고, 일부 면 병합과 표면 정리, 절단면 두께 보강을 진행했다. 가슴 판의 불필요한 표면 굴곡도 줄였다.

![[20261110-npc10-armor-v13-parts.png]]

Blender 작업본은 **74개 편집 파츠**로 정리했다. 이 중 단단한 판으로 관리하는 파츠는 53개다. 편집할 때는 개별 판을 선택할 수 있고, 언리얼에 내보낼 때는 공통 뼈대를 쓰는 메시로 묶었다. 게임에서 파츠 74개를 각각의 컴포넌트로 그리는 구조는 아니다. 최종 재질 슬롯과 메시 섹션은 기존과 같은 12개다.

| 구분 | 움직이는 방식 |
| --- | --- |
| 가슴·등·허리 판 | 기준 뼈를 따라 단단한 형태 유지 |
| 어깨 보호대 | 팔 움직임을 일부 따라가는 보조 뼈 |
| 팔꿈치·무릎 보호대 | 관절 양쪽 움직임을 절충하는 보조 뼈 |
| 앞·뒤 가림판 | 상단 고정점에서 각각 하나의 판으로 회전 |
| 옆 허리 장갑 | 좌우 다리 움직임에 맞춰 들리는 보조 뼈 |
| 안감·손가락 | 관절을 따라 부드럽게 변형 |

기존 뼈 59개를 유지하고 **갑옷 보조 뼈 10개**를 추가했다. 단단한 판에는 기준 뼈 하나의 웨이트를 적용해 고무처럼 늘어나지 않도록 했다. 갑옷 사이로 보이는 검은 안감도 별도로 정리했다.

### 관절을 움직여 확인하기

![[20261110-npc10-armor-v13-upper-joints.png]]

어깨 판은 팔의 회전을 그대로 100% 따라가지 않고 일부를 따라가도록 했다. 팔꿈치와 무릎 판도 관절 중간 방향으로 움직인다. 언리얼의 공용 `ArmorRigAnimInstance`가 일반 애니메이션 계산 뒤 보조 뼈만 보정하므로, 몸의 움직임과 얼굴 표정은 유지한다.

![[20261110-npc10-armor-v13-lower-joints.png]]

사타구니와 엉덩이 가림판은 **가운데를 갈라놓지 않고 앞·뒤 각각 하나의 연속된 판**으로 만들었다. 두꺼운 골반 덩어리를 잘라 움직이는 대신 약 3mm 두께의 얇은 판으로 정리하고, 고정점을 실제 판의 상단으로 옮겼다. 다리를 들면 판이 통째로 들리며 형태를 유지한다.

검사 중에는 Blender와 언리얼의 좌표 변환 때문에 가림판이 몸 안쪽으로 도는 문제도 확인했다. 가져온 뼈대의 전방·위쪽 방향에서 회전축을 계산하도록 수정했다. 캐릭터를 90도 돌린 상태에서도 같은 앉기 자세의 가림판 보정값이 유지되는지 확인했다.

![[20261110-npc10-armor-v13-squat-grip.png]]

앉기·쪼그리기·다리 들기·손가락 굽힘은 관절 확인용 자세다. NPC가 의자를 찾아 앉거나 무기를 잡는 게임 행동까지 추가한 것은 아니다. 새로운 공격 동작이나 의자에 적용할 때는 해당 자세의 간격을 확인해야 한다.

### 애니풍에서도 금속처럼 보이게 만들기

![[20261110-npc10-armor-v13-metal-light.png]]

![[20261110-npc10-armor-v13-expressions.png]]

## VRoid 템플릿 분석과 노란 꽃무늬 원피스 시험

Meshy 의상을 보정하는 작업에 이어, **GPT로 의상 텍스처를 만들고 VRoid Studio의 템플릿에 직접 적용하는 방식**을 시험했다. 갈색 머리와 노란 머리핀, 노란 꽃무늬 원피스 소녀가 목표다. VRoid Studio 2.14.0에서 실제 기본 텍스처를 내보내 적용했고, 기본 샘플 B·R·V의 헤어와 의상 구조도 살펴봤다.

### 샘플 B의 머리핀과 장식용 헤어 메시

![[20261110-vroid-sample-b-hairpin.jpg]]

B의 헤어 목록에는 머리핀과 귀걸이 같은 장식용 가이드가 따로 있었다. 작은 평면 메시와 투명 배경 텍스처를 조합하면 헤어 편집 도구로 머리카락 이외의 장식도 만들 수 있다. 노란 머리핀도 의상 PNG에 그리는 것만으로 생기는 것이 아니라, 별도 형태와 재질을 준비해야 한다.

B의 재킷은 롱코트(하이넥)의 앞과 밑단을 투명하게 가려 짧은 형태로 표현했다. **텍스처의 투명 영역은 불필요한 옷 부분을 숨기고, 템플릿 수치는 남은 부분의 부피와 실루엣을 조절한다.**

### 샘플 R과 V의 의상 겹치기

![[20261110-vroid-sample-r-coat-layers.jpg]]

R에서는 롱코트(하이넥)를 겹쳐 겉 코트, 조끼·셔츠, 크라바트·소맷단을 나누는 구성을 확인했다. 화면에서 최소 3개 겹을 관찰했으며, 전체 수를 3개로 확정한 것은 아니다. 같은 템플릿을 쓰더라도 각 겹의 텍스처와 형태 값은 독립적이다.

![[20261110-vroid-sample-v-cape-lining.jpg]]

V의 상의는 어깨 망토·칼라, 본체, 프릴·소맷단, 긴 검은 망토, 붉은 안감의 5개 구성으로 나뉘어 있었다. 긴 망토 겉면의 전체 볼륨은 90, 안감은 88이었다. 이 값은 해당 샘플의 관찰값이며, 새 의상에 그대로 쓰는 공통 정답은 아니다.

샘플에는 전체 볼륨 120, 어깨 패드 -25, 소매 관련 값 200처럼 슬라이더 표시 범위를 벗어난 값도 있었다. 일부 항목은 숫자를 직접 입력해 범위를 확장할 수 있지만, 새 의상은 먼저 적절한 템플릿과 투명 영역, 필요한 겹으로 형태를 잡기로 했다. 얼굴·헤어·의상은 수치의 단위와 기본 범위도 다르다.

### 디자인 이미지에서 실제 착용 텍스처로 옮기기

작업 순서는 **디자인 확인 → 템플릿 선택 → 기본 PNG와 UV 가이드 내보내기 → UV 배치를 유지한 이미지 편집 → VRoid 착용 → 형태 값 조절 → 앞뒤와 측면 검토**로 정리했다. 앞뒤 디자인 일러스트는 참고 이미지이며, 그대로 의상 텍스처 칸에 넣는 파일과 구분한다.

옷의 실제 넓이·길이는 메시 설정으로 바꾸고, 꽃무늬의 크기·간격은 텍스처에서 바꾼다. PNG의 해상도를 키워도 옷의 폭이 넓어지는 것은 아니다. 같은 원피스 분류 안에서도 템플릿이 다르면 UV와 설정 항목이 달라지므로 텍스처와 수치를 한 묶음으로 기록해야 한다.

![[20261110-vroid-yellow-dress-applied.jpg]]

노란 의상은 **원피스(반팔) 템플릿의 기본 적용 시험본**이다. 치마 넓히기·밑단 넓이·허리 느슨하게·치마 길이·치마 볼륨 주기·치마 조이기·소매 조임·어깨 라인 정리를 모두 0으로 적용했다. 머리색은 갈색 `#865B44`로 맞췄다.

이 시험본은 템플릿의 높은 목선을 유지하고 있으며, 목표인 노란 머리핀과 새 헤어 텍스처는 아직 만들지 않았다. 디자인 완성 승인본과 구분해 보관했다. AI 텍스처 원본은 1254×1254였고 VRoid에서 2048×2048 RGBA로 내보냈다. 규격을 맞춘 것이며 원본에 없던 세부 묘사가 추가된 것은 아니다.

적용할 때는 `의상 → 원피스 → 사용자 지정 → 새로 만들기 → 원피스(반팔) → 텍스처 편집`에서 기본 이미지 레이어를 불러온 PNG로 교체한다. `.vroidcustomitem`을 가져오면 텍스처와 템플릿 설정을 함께 재사용할 수 있다. 이 PNG와 수치를 롱코트(하이넥)에 그대로 넣어 쓰지 않는다.

### 다른 컴퓨터에서 이어갈 자료 남기기

노란 원피스 작업은 `VRoid_작업기록/2026-11-10_노란꽃원피스_샘플분석/Portable_VRoid_20261110.zip`에 묶었다. 편집용 `.vroid`, 의상 아이템, PNG, 설정 JSON, 프롬프트, 실제 샘플 캡처와 `HANDOFF.txt`, `report.html`을 포함했다.

다른 PC에서는 묶음을 풀고 `.vroid`를 열어 작업을 이어갈 수 있다. 더퀸 Unreal 프로젝트와 이전 Meshy·Blender 원본은 별도로 옮겨야 한다. 이번에는 로컬 파일 묶음을 준비했으며 클라우드 업로드는 하지 않았다.


## Test3 은색 중세 병사와 헤어 투구 제작

이어서 Test01 남성 캐릭터를 기반으로 **VRoid Studio에서 직접 편집할 수 있는 은색 중세 병사 Test3**를 만들었다. 가슴에는 남색 방패와 은색 8각 별의 기사단 문장을 넣었다. 투구는 앞서 작업한 NPC10 디자인의 둥근 덮개, 올려진 통풍구 바이저, 귀와 볼 옆 보호판을 기준으로 맞췄다.

![[20261110-test3-helmet-front-latest.png]]

위 이미지는 마지막 저장본의 실제 VRoid 상반신 캡처다. 갑옷의 넓은 은색 면, 검은 관절 안감, 벨트, 가운데가 이어진 가림판을 템플릿과 전용 텍스처로 구성했다. 원본 남성의 얼굴과 체형은 유지하고 검은 장갑과 끈 부츠를 적용했다.

### 상의와 하의의 템플릿 맞추기

상의는 **롱코트(하이넥)**, 하의는 **바지(주름 없음)**를 사용했다. 실제 기본 텍스처의 UV를 기준으로 가슴·등·팔·허벅지·무릎·정강이의 위치를 맞췄다. 긴 코트 전체를 은색으로 덮지 않고 필요한 부분을 남겨 허리와 골반의 갑옷 윤곽을 만들었다. 다리 뒤에는 검은 패딩과 가죽끈을 표현했다.

![[20261110-test3-full-front-stage.png]]

이 전신 정면은 **투구 본체 깊이와 바이저 간격을 마지막으로 조절하기 전**에 촬영했다. 상의·하의·장갑·부츠 구성은 확인할 수 있으며, 투구의 최신 형태는 위 근접 정면과 아래 측면을 기준으로 본다.

위 수치는 이 캐릭터와 해당 템플릿에 맞춘 값이다. 다른 체형에 입힐 때는 어깨·허리·목과 관절의 간격을 다시 확인한다. 특히 투구의 -300은 챙을 줄이기 위해 이번 형태에 사용한 값이며, 다른 의상에 적용할 권장 범위가 아니다.

### 모자 본체와 헤어 보호판을 조합한 투구

처음의 챙 넓은 모자형 투구에서, 머리에 맞춘 둥근 덮개와 별도 보호판을 조합하는 방향으로 수정했다. 사용자가 직접 조절한 투구 둘레와 위치를 보존하고, 옆머리 사용자 지정 아이템에 프로시저 헤어 3개를 만들어 좌우 보호판과 바이저로 사용했다.

![[20261110-test3-helmet-side-latest.png]]

처음 보호판을 평판 단면으로 만들었을 때는 정면에서 날개처럼 벌어지거나 각도에 따라 면이 사라져 보였다. 좌우 비틀림을 반대로 맞추고, **마름모꼴 단면으로 두께를 준 뒤 머리와의 간격을 줄였다.** 텍스처 가로 배율도 보호판 폭에 맞춰 테두리와 리벳이 늘어나지 않게 조절했다.

바이저에는 세로 통풍구 6개를 넣었다. 머리에서 너무 멀면 떠 보이고 너무 가까우면 머리카락과 본체가 뚫고 나와, 정면과 측면을 번갈아 보며 오프셋을 조절했다.

금속용 재질에서는 헤어의 메인 색과 하이라이트 색 적용을 해제했다. 갈색 머리 재질과 분리해 보호판까지 갈색으로 물드는 것을 막았다. 투구용 세 그룹은 흔들림 설정의 **본 미설정** 상태로 유지해 머리카락처럼 흔들리는 본을 추가하지 않았다.

### 후면 간섭과 저장본 확인

![[20261110-test3-full-back-stage.png]]

후면에서는 머리카락이 투구 위로 비치는 부분을 발견해 본체 볼륨과 앞뒤 깊이를 보정했다. 큰 돌출은 줄였지만 근접 후면의 작은 점 수준 간섭은 재개 후 다시 확인할 항목으로 남겼다. 위 후면 사진은 본체 깊이 보정 후, 바이저 간격의 마지막 수정 전에 촬영한 기록이다.

| 파일 | 용도 |

### 현재 방식의 한계와 재개할 작업

이번 갑옷은 **VRoid 템플릿에 판금 무늬와 명암을 그려 입힌 방식**이다. 앞서 Blender에서 각 판을 분리하고 보조 뼈를 붙인 NPC10 갑옷과는 제작 구조가 다르다. 투구는 열린 고정 형태이며 실제로 열고 닫히는 힌지 애니메이션은 없다.

VRoid의 대기 자세와 정면·측면·후면을 확인한 상태다. 새 Test3의 언리얼 적용과 걷기·달리기 리타게팅은 아직 진행하지 않았다. 작업 재개 후에는 최신 전신 캡처, 동작 중 간섭, 투구 후면을 확인하고, 상의·하의·보호판의 사용자 지정 아이템을 Test3 폴더에 모아 재사용 자료를 마무리한다.

이번 과정에서 배운 점은 **템플릿과 UV, 겹별 설정, 장식용 메시, 실제 착용 검토를 함께 설계해야 한다**는 것이다. 텍스처 생성만으로 의상의 입체 형태와 리깅까지 자동으로 완성되지는 않는다.

노란 원피스 시험과 Test3 제작에서는 **Meshy 호출 0회, Meshy 크레딧 사용 0**이다. GPT 이미지 생성으로 텍스처를 제작한 과정과는 구분한다. 이번 추가 기록은 **실제 정지 캡처 8장, 새 GIF 0개**로 정리했다.
