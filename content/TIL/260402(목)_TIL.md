랜덤 상자 파밍 루프

맵 이동 (A → B) → 상자 스폰 여부 체크 → 상자 종류 결정 (없음 / 일반 / 고급) → 상자 개봉 → 보상 결정 (장비 / 동료 : 능력치 랜덤) → 결과 확인 → 반복 이동

## \[내일배움캠프 사전캠프 4일차\]서버, 클라이언트 기본 개념

\[서버 · 클라이언트 기초 개념 정리\]

**1. 기본 구조**

**클라이언트(Client)**

- 서버에 요청(Request) 을 보내는 프로그램, 사용자와 상호작용
- 웹 클라이언트 : 브라우저 (크롬 등)
- 게임 클라이언트 : 게임 실행 프로그램

**서버(Server)**

- 클라이언트의 요청을 받아 처리 후 응답(Response) 반환
- 웹 서버 : 페이지, 이미지 등 정적인 콘텐츠 전송, 브라우저 요청(http/https)
- 게임 서버 : 플레이어 데이터, 위치, 전투 처리

**2. 요청 / 응답 구조**

- 요청 (Request) : 클라이언트 → 서버
- 응답 (Response) : 서버 → 클라이언트

**3. 프로토콜 (Protocol)**

- 데이터 통신 규칙 (서로 약속된 방식)

|  |  |
| --- | --- |
| **종류** | **특징** |
| **HTTP / HTTPS** | 웹 통신 (요청-응답 구조) |
| **TCP** | 느리지만 안정적 (데이터 보장) |
| **UDP** | 빠르지만 일부 손실 가능 (실시간에 유리) |

**4. 서버 vs 클라이언트 역할 정리**

|  |  |
| --- | --- |
| **구분** | **역할** |
| **클라이언트** | 요청 보내고 결과 화면에 표시 |
| **서버** | 데이터 처리, 결과 계산, 응답 반환 |

**5. 웹 서버 vs 게임 서버**

|  |  |  |
| --- | --- | --- |
| **구분** | **웹 서버** | **게임 서버** |
| **통신 방식** | HTTP | TCP / UDP |
| **구조** | 요청-응답 중심 | 실시간 처리 |
| **특징** | 정적/간단 데이터 | 위치, 전투, 동기화 처리 |

**6. 게임 클라이언트 개발 도구**

|  |  |
| --- | --- |
| **엔진** | **특징** |
| **유니티** | 가볍고 빠름, 모바일/인디/VR |
| **언리얼** | 고퀄리티, AAA, 그래픽 중심 |

**7. 네트워크 구조**

**서버 구조**

- 단일 서버 : 하나가 모든 처리 (간단, 한계 있음)
- 분산 서버 : 여러 서버로 역할 분리 (대규모 서비스)
- P2P : 서버 없이 클라이언트끼리 직접 연결
- 하이브리드 : 일부 서버 + 일부 P2P

**8. 서버 확장 방법**

|  |  |
| --- | --- |
| **방식** | **설명** |
| **수직적 확장(Scale Up)** | 서버 성능 업그레이드 |
| **수평적 확장(Scale Out)** | 서버 여러 대로 분산 |

## \[내일배움캠프 사전캠프 4일차\] 게임 개발 구조 및 역활 정리

**\[게임 개발 조직 구조 및 역할 정리\]**

**1. 의사결정권자(디렉터)**

- **PD (Project Director) :** 프로젝트 총괄 책임자 (전체 방향 결정)
- **TD (Technical Director) :** 기술 방향 및 개발 구조 결정
- **AD (Art Director) :** 아트 스타일 및 비주얼 방향 결정자

**2. 방향성 결정**

- **장르 선택** : RPG, FPS, 액션 등
- **타겟층 설정** : 연령, 플랫폼(모바일/PC), 캐주얼/하드코어  등
- **컨셉 정의** : 분위기, 세계관, 핵심 재미 요소

**3. 주요 직군**

- **게임 기획자 :** 게임 시스템, 규칙, 콘텐츠 설계
- **아트 :** 게임 전체 분위기(배경, UI, 원화, 모델러, 애니메이터, VFX)
- **프로그래머 :** 게임 기능 구현 및 시스템 개발
- **QA :** 테스터, 버그 발견, 게임 품질 검증

## \[내일배움캠프 사전캠프 4일차\]언리얼 엔진 게임 프레임워크 기본 구조 정리

**\[언리얼 엔진 게임 프레임워크\]**

**구성 요소**

**PlayerController**

플레이어 입력을 처리하는 객체 , 키보드 / 마우스/ 컨트롤러 입력 담당

**Pawn**

플레이어 또는 AI가 “조종하는 대상” , 움직임의 실제 주체

**Character**

Pawn을 상속 ,  이동, 점프 등 기본 기능이 추가된 캐릭터 클래스

**AIController**

AI가 Pawn을 제어할 때 사용

**UMG (UI)**

언리얼 엔진에서 UI를 제작하는 시스템

**Actor 생명주기**

생성(Spawn) → 초기화 → BeginPlay(게임 시작 시 1회 실행)

→ Tick(매 프레임 실행 : 반복) → Destroy(객체 제거)

**Pawn:**

Actor를 상속받아, Controller에 의해 조종되는 객체

**Character:**

Pawn을 상속받아, 이동, 점프 기능 등이 추가된 캐릭터 클래스

**Component:**

Actor에 붙어서 기능을 추가하는 구성 요소, 단독으로 존재하지 않고 Actor에 종속

**이벤트 시스템**

**BeginPlay :** 시작 시 실행

**Tick :** 매 프레임 실행

**OnOverlap :** 충돌 시 실행
