# OST 쇼츠 제작과 개발 기록, 옵시디언 연결

게임에서 만든 노래와 플레이 장면을 외부에 보여 줄 자료로 정리했다. OST 영상은 노래와 화면이 자연스럽게 이어지도록 편집하고, 블로그는 최신 캡처로 기능과 제작 과정을 설명하는 데 집중했다.

## 1. 여섯 곡에 서로 다른 게임 장면 넣기

OST 여섯 곡의 제목은 유지하고, 그 아래에 게임 화면을 넣었다. 곡마다 다른 5초 장면들을 섞고 가사는 중간 아래에 크게 배치했다. 노래방처럼 진행되는 색은 파란색으로 맞췄다.

![[TIL/첨부파일모음/20261117-sinbi-ost-karaoke.jpg|300]]

〈Starlight Run〉은 마지막 **shine tonight** 부분의 색 채움이 노래보다 일찍 끝났다. 자동으로 맞춘 마지막 단어 시간을 다시 조정해 길게 부르는 구간까지 따라가도록 수정했다.

## 2. 일곱 채널에 OST 게시

YouTube·Instagram·TikTok·X·Threads·Facebook·네이버 클립에 여섯 곡을 게시했다. 제목은 **곡명 | IDOL SINBI OST**로 통일하고, Gemini로 만든 AI 음악·보컬임을 설명과 플랫폼 표시로 알렸다.

YouTube의 관련 동영상 기능은 별도 인증을 진행하지 않고 제외했다. 대신 설명에 게임 플레이 영상 주소를 넣는 방식으로 정리했다.

## 3. 기능 소개와 트러블슈팅 글 정리

프로젝트 소개, 구현기능, 트러블슈팅을 나눠 글을 작성했다. 현재 기능은 최신 영상과 캡처를 사용하고, 삭제된 기능은 당시 자료로 구분했다.

글씨가 작은 설명을 여러 개 붙이거나 PPT 카드처럼 과하게 꾸미기보다, **큰 실제 화면과 짧은 설명**으로 정리하는 방향으로 수정했다. 기능 흐름은 따로 도식으로 보여 주되 글자 크기와 간격을 다른 글들과 맞췄다.

## 4. SSD의 블로그를 옵시디언과 연결

옵시디언 보관함으로 열고 Git과 SourceTree 연결을 정리했다.

다른 PC에서 사용하던 폴더의 소유자 정보 때문에 Git이 저장소를 신뢰하지 않는 문제가 있었다. 드라이브 문자만의 문제가 아니어서, 해당 저장소 경로만 신뢰하도록 등록했다.

**커밋은 PC 안에 변경 기록을 남기고, 푸시는 그 기록을 GitHub에 업로드한다.** 자동 푸시는 꺼 두고 직접 실행하는 방식으로 유지했다. 전체 프로젝트의 릴리즈 압축 업로드는 중간에 취소했으므로, 소스 관리 기록을 전체 에셋 백업으로 보지 않도록 구분했다.
