**2. 내용**

1. 프로젝트 개요

- 발표회 주제 : 주말

- 프로젝트명: 배고파 (1인 가구 식단 시뮬레이션)

- 개발 언어: C++

- 핵심 컨셉: 주말 하루 동안 아침, 점심, 저녁 세 끼를 해결하며

'만족도'와 '카드값' 사이의 균형을 맞추는 텍스트 기반 시뮬레이션 게임.

2. 주요 기능 및 로직

식재료 및 레시피 시스템 (FoodManager)

- 데이터 관리: vector와 struct를 활용해 배달 음식, 식재료 가격, 레시피 데이터를 구조화

- 레시피 매칭: 사용자가 입력한 재료 리스트를 정렬(std::sort)한 뒤, 미리 정의된 레시피 리스트와 비교하여 요리 성공 여부를 판정

냉장고 인벤토리 (Fridge)

- 자료구조: map<string, int>를 사용하여 식재료의 이름(Key)과 수량(Value)을 효율적으로

관리했습니다.

- 기능: 재료 추가, 수량 확인, 요리 시 재료 소모 로직을 포함합니다.

요리 및 배달 시스템 (CookedFood, DeliveryFood)

- 요리: 냉장고에 있는 재료를 조합합니다. 성공 시 높은 만족도를 얻지만 재료가 필요합니다.

- 배달: 재료가 없어도 간편하게 해결 가능하지만, 카드값이 크게 상승하고 만족도는 음식마다 상이합니다.

게임 관리 및 엔딩 시스템 (GameManager)

- 상태 관리: satisfaction(만족도), cardCost(카드값), deliveryCount(배달 횟수)를 추적합니다.

- 다중 엔딩: 하루가 끝난 후 배달 횟수 / 지출 금액 / 만족도의 3가지 요소를 조합하여 약 64가지(4x4x4) 조합의 다양한 엔딩 문구를 출력합니다.

(예: '프로 자취생', '카드값 폭탄', '미슐랭 자취생' 등)

3. 핵심 코드 분석

요리 판정 로직 (Recipe Matching)

단순히 재료의 포함 여부만 보는 것이 아니라, 벡터를 정렬하여 구성 요소가 완전히 일치하는지 확인하는 방식을 사용했습니다.

```
// 사용자가 입력한 재료(a)와 레시피 재료(b) 비교
sort(a.begin(), a.end());
sort(b.begin(), b.end());

if (a == b) 
{
   // 요리 성공!
}
```

4. 이번 프로젝트를 통해 배운 점 (Retrospective)

1. STL의 활용: vector와 map을 실무적인 데이터 관리(인벤토리, 레시피)에 적용해 보며 각 자료구조의 장단점을 이해했습니다.

2. 객체 지향 설계: GameManager, FoodManager, Fridge 등으로 역할을 나누어 관리함으로써 코드의 가독성과 유지보수성을 높였습니다.

3. 예외 처리: 사용자가 없는 재료를 입력하거나 잘못된 번호를 입력했을 때의 예외 로직을 구성하며 프로그램의 안정성을 고민했습니다.

4. 엔딩 분기 로직: 여러 변수를 조합하여 사용자에게 다양한 피드백을 주는 '결과 테이블' 시스템을 설계해 보았습니다.
