# 마이크 노래 채점과 박자 타자, 첫 게임 UI 연결

콘서트 여행의 기획을 정리하고, 월드와 분리한 기능 시험 맵에서 공연의 기본 흐름을 만들었다. 화면만 만드는 데서 끝내지 않고 **입력 → 채점 → 결과 → 보상**이 이어지도록 작업했다.

## 1. 마이크로 부른 노래를 점수로 연결

12초 시험곡을 사용해 마이크 입력에서 음정과 박자를 읽도록 했다. 입력 소리를 게임 안에서 분석하고, 공연이 끝나면 결과와 보상을 정산하는 방식이다. 원본 목소리는 녹음하거나 외부로 전송하지 않았다.

처음에는 마이크 접근 권한과 첫 오디오 버퍼 처리 때문에 입력이 정상적으로 이어지지 않았다. 권한을 확인하고, 첫 입력 패킷의 상태를 처리하는 부분을 수정한 뒤 직접 한 소절을 불러 결과가 나오는 것을 확인했다.

![[TIL/첨부파일모음/20261113-sinbi-mic.jpg|700]]

이 단계에서는 짧은 시험곡으로 마이크 입력과 정산을 먼저 연결했다. 실제 공연곡과 긴 가사의 타이밍은 이후 작업에서 맞추기로 했다.

## 2. 마이크가 없을 때는 박자 타자

가사에 맞춰 단어를 입력하고 Enter로 제출하는 타자 방식을 함께 만들었다. 노래와 타자는 같은 공연 흐름을 사용하되, **타자 모드의 보상은 노래의 0.5배**로 구분했다.

일시정지할 때는 반주와 가사 진행도 함께 멈추고, 다시 시작하면 같은 지점에서 이어지도록 했다. 결과 창에서 보상이 두 번 지급되지 않도록 정산도 한 번만 처리했다.

## 3. PC용 UI를 아홉 화면으로 정리

시작 메뉴·로딩·HUD·메뉴·공연 준비·공연 결과·NPC 대화·설정·이어하기 화면을 정리하고 WBP에 반영했다. PC 화면에서 게임 장면이 충분히 보이도록 크기와 배치를 조정했다.

![[TIL/첨부파일모음/20261113-sinbi-start-wbp.jpg|700]]

첫 메인 메뉴를 적용한 모습이다. 이후에는 게임 기능과 최종 범위에 맞춰 화면을 계속 수정했다.

## 4. 문구와 화면 데이터를 분리

UI 문구는 이미지에 넣지 않고 **String Table**에서 관리하는 방향으로 잡았다. 
언어가 바뀌면 같은 버튼의 문구도 바뀌게 하기 위해서다.

게임 수치와 화면 표현은 MVVM으로 연결했다. 
화면이 매번 값을 찾아 읽기보다, HP나 인기도 같은 값이 바뀔 때 UI에 전달하는 구조로 작업했다. 
공연 규칙, 선물과 팬심, 동료, 영감 성장도 기획 문서에 함께 정리했다.
