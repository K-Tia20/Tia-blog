\[Project Retrospective\] C++ 기반 서사 중심 RPG: HaremTextRPG

객체 지향 설계와 데이터 드리븐 시스템을 활용한 인터랙티브 스토리텔링 프레임워크

**1. Project Overview**

\* 개발 환경: C++, Visual Studio or JetBrains Rider, Win32 API (Sound/UI)

\* 핵심 컨셉: 텍스트와 이미지를 결합한 서사 중심의 RPG로, 캐릭터 간 상호작용과 상태 변화에 따른 멀티 엔딩 시스템 구현

\* 주요 성과: 객체 지향 프로그래밍(OOP)을 통한 캐릭터/장소 모듈화, 외부 리소스(이미지/사운드) 관리 시스템 구축,

스크립트 기반의 시나리오 엔진 구현

**2. Key Technical Features (기술적 특징)**

**① 객체 지향 기반의 캐릭터 및 장소 시스템 (Creature & Area)**

**상속과 다형성 활용:**

Creature와 Area라는 최상위 추상 클래스를 설계하여 공통 속성(이름, 상태값, 이벤트)을정의했습니다.

**확장성 확보:**

이를 상속받은 Lina, Elizabeth 등 개별 캐릭터와 City, Shop, Alba 등의 장소를 독립적인 모듈로 구현하여 새로운 콘텐츠 추가 시 기존 코드의 수정을 최소화했습니다.

**② 데이터 드리븐 시나리오 엔진 (ScriptManager & Scenario.txt)**

**로직과 데이터의 분리:**

게임의 대사와 선택지 흐름을 코드 내 하드코딩하지 않고 외부 Scenario.txt 파일에서 관리하도록 설계했습니다.

**스크립트 파싱:**

ScriptManager를 통해 텍스트 데이터를 분석하여 상황에 맞는 이미지 변경, 사운드 출력, 캐릭터 호감도  변화 등의 이벤트를 트리거합니다.

**③ 리소스 관리 및 UI 프레임워크 (UIManager & ImageManager)**

**이미지 렌더링 최적화:**

stb\_image.h를 활용하여 PNG 등 다양한 포맷의 이미지를 로드하고, ImageManager를 통해 메모리 누수 없이 효율적으로 텍스트와 함께 출력하는 시스템을 구축했습니다.

**멀티미디어 통합:**

CSoundManager를 통해 BGM과 SE(효과음)를 상황별로 제어(Fade-in/out 등)하여 게임의 몰입도를 높였습니다.

**④ 전투 및 경제 시스템 (BattleSystem & Inventory)**

**복합적 게임 루프:**

단순 텍스트 선택을 넘어 BattleSystem을 통한 수치 기반의 긴장감을 조성하고, Inventory와 Shop 시스템을 통해 아이템 획득 및 재화 관리의 재미를 추가했습니다.

**3. Challenges & Solutions (문제 해결 경험)**

문제:

수많은 캐릭터와 장소가 늘어남에 따라 의존성(Dependency)이 복잡해지는 문제 발생.

해결:

World 클래스를 통해 전체 게임 상태를 관리하는 싱글톤 패턴(또는 중앙 집중 관리 방식)을 적용하고, DelegateManager를 도입하여 객체 간의 직접적인 참조를 줄여 결합도를 낮췄습니다.

---------------------

문제:

텍스트 출력과 이미지 변경 시의 싱크 및 화면 깜빡임 현상.

해결:

더블 버퍼링 개념을 응용하여 UI 업데이트 로직을 최적화하고, 로그 시스템(LogSystem)을 별도로 분리하여 디버깅 및 사용자 피드백 가독성을 확보했습니다.

**4. Retrospective (자기 성찰)**

\[Project Retrospective\] C++ 기반 데이터 드리븐 비주얼 노벨 & RPG 엔진 개발

본 프로젝트는 C++을 사용하여 비주얼 노벨의 서사 구조와 RPG의 성장/전투 시스템을 결합한 통합 게임 엔진 프레임워크를

구축한 사례입니다.

1. 아키텍처 및 설계 전략 (Architecture & Design)

① 중앙 집중형 월드 상태 관리 (C\_World)

\* 싱글톤 패턴(Singleton Pattern)을 적용하여 게임의 생명주기와 전역 상태(날짜, 위치, 플레이어 상태)를 안정적으로

관리했습니다.

\* 컴포넌트 기반 설계: UIManager, C\_BattleSystem, C\_Player 등을 멤버로 보유하여 시스템 간의 의존성을 체계적으로

분리했습니다.

\* Dirty Flag 패턴: UI 업데이트 시 모든 요소를 매번 그리는 대신, 변경된 데이터만 동기화(SyncUI)하여 렌더링 효율을

높였습니다.

② 추상화 기반의 객체 모델링 (Creature & Area)

\* 계층적 상속 구조: C\_Creature 추상 클래스를 통해 히로인과 적(Enemy)의 공통 속성(Affinity, HP, Attack)을 정의하고,

이를 상속받아 개별 캐릭터의 특화된 로직을 구현했습니다.

\* 다형성 활용: 성격(Style)에 따른 동적 이미지 매핑(GetImageKey) 및 이름 색상화(GetColoredName)를 통해 시각적 요소를

코드 레벨에서 유연하게 처리했습니다.

2. 핵심 기술 구현 (Key Technical Features)

① 데이터 드리븐 시나리오 엔진 (C\_ScriptManager)

\* 스크립트 파싱: 하드코딩을 배제하고 Scenario.txt로부터 데이터를 동적 로드하는 시스템을 구축했습니다.

\* 가변 인자 템플릿(Variadic Templates): 플레이어 이름이나 특정 수치를 대사 내에 실시간으로 치환하기 위해 {0}, {1}

식의 플레이스홀더 시스템(GetFormat)을 구현하여 서사의 유연성을 확보했습니다.

② 이벤트 중재 시스템 (DelegateManager)

\* 시스템 간 디커플링: UI와 전투 시스템 간의 직접적인 참조를 줄이기 위해 DelegateManager를 도입하여 이벤트 바인딩을

중재했습니다. 이는 코드의 확장성과 유지보수성을 극대화하는 결과로 이어졌습니다.

③ 콘솔 기반 그래픽 및 UX 프레임워크 (UIManager)

\* ANSI 이스케이프 코드: 텍스트 기반 환경에서 색상과 레이아웃을 제어하기 위해 ANSI 코드를 적극 활용했습니다.

\* 레이아웃 엔진: 스마트폰 프레임, 솔리드 박스 렌더링, 텍스트 타이핑 효과(TypeLog)를 통해 사용자 몰입도를 높였습니다.

\* 리소스 관리: stb\_image.h를 통합하여 외부 이미지 자산을 로드하고 처리하는 리소스 파이프라인을 구축했습니다.

3. 도전 과제 및 해결 (Challenges & Solutions)

\* 문제: 다수의 시스템이 얽히면서 발생하는 코드 비대화 및 스파게티 코드 위험.

\* 해결: 기능별로 폴더 구조를 엄격히 분리(Areas, Battle, UI, Framework)하고, Defs.h를 통해 공통 상수 및 타입을

정의하여 코드 일관성을 유지했습니다.

\* 문제: 콘솔 환경의 제한적인 렌더링 성능.

\* 해결: ClearMainViewport 및 부분 렌더링 로직을 통해 불필요한 화면 깜빡임을 최소화하고, 사용자 입력

대기(WaitEnterSilent) 로직을 최적화했습니다.
