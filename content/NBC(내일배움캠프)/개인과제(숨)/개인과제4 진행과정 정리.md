언리얼 엔진 5(UE5)에서 향상된 입력 시스템(Enhanced Input System)을 사용해 물리 기반이 아닌, 코드 제어로 움직이는 Pawn을 구현하는 전체 과정입니다. 코드를 제외하고 **작업 단계와 에디터 설정 중심**으로 자세히 정리해 드렸습니다.

## 1단계: C++ 클래스 생성 및 컴포넌트 구성

### 1. C++ 클래스 생성

1. 언리얼 에디터 상단 메뉴에서 **Tools > New C++ Class**를 선택합니다.
    
2. 부모 클래스로 **Pawn**을 선택하고 이름을 지정한 뒤 클래스를 생성합니다.
    
3. 비주얼 스튜디오(또는 사용 중인 IDE)가 열리면 헤더 파일(`.h`)과 소스 파일(`.cpp`)에서 작업을 시작합니다.
    

### 2. 컴포넌트 선언 및 생성 (헤더 & 소스 변수 작업)

- **헤더 파일(`.h`)**: 컴포넌트들을 가리킬 포인터 변수들을 `private` 또는 `protected` 영역에 선언합니다. 블루프린트에서 세부 수치를 수정할 수 있도록 `UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Components")` 매크로를 붙여줍니다.
    
    - `UCapsuleComponent* CollisionComp;` (충돌체)
        
    - `USkeletalMeshComponent* MeshComp;` (외형 Mesh)
        
    - `USpringArmComponent* SpringArmComp;` (카메라 지지대)
        
    - `UCameraComponent* CameraComp;` (카메라)
        
- **소스 파일(`.cpp`)의 생성자 (`AMyPawn::AMyPawn()`)**: `CreateDefaultSubobject<T>()` 함수를 사용해 위에서 선언한 컴포넌트들의 인스턴스를 실제로 생성합니다.
    

### 3. 계층 구조(Attachment) 설정 및 물리 끄기

생성자 내부에서 컴포넌트들의 부모-자식 관계를 정립하고 물리 설정을 해제합니다.

1. **Root 설정**: 충돌 컴포넌트(`CollisionComp`)를 `RootComponent = CollisionComp;`로 지정하여 최상단 부모로 만듭니다.
    
2. **자식 부착**: `SetupAttachment()` 함수를 사용하여 계층 구조를 만듭니다.
    
    - `MeshComp` -> `RootComponent`에 부착
        
    - `SpringArmComp` -> `RootComponent`에 부착
        
    - `CameraComp` -> `SpringArmComp`에 부착 (카메라가 붐대 끝에 달리도록)
        
3. **물리(Physics) 비활성화**: 코드 제어 이동을 위해 루트 충돌체와 메쉬 컴포넌트의 물리 시뮬레이션을 명시적으로 끕니다.
    
    - 각 컴포넌트의 `SetSimulatePhysics(false)`를 호출합니다.
        

## 2단계: 입력 에셋 생성 및 매핑 (에디터 작업)

### 1. 입력 액션(IA) 생성

1. 에디터 콘텐츠 브라우저에서 우클릭 후 **Input > Input Action**을 두 개 생성합니다.
    
2. 이름을 `IA_Move`, `IA_Look`으로 지정합니다.
    
3. 각 입력 액션을 더블 클릭해 열고, **Value Type**을 기본 `Digital (bool)`에서 Axis2D (Vector2D)로 변경하고 저장합니다.
    

### 2. 입력 매핑 컨텍스트(IMC) 설정

1. 콘텐츠 브라우저 우클릭 후 **Input > Input Mapping Context**를 생성하고 이름을 `IMC_Pawn`으로 지정합니다.
    
2. `IMC_Pawn`을 열어 **Mappings** 배열에 위에서 만든 두 액션을 추가합니다.
    
3. **IA_Move (WASD 이동)** 키 매핑:
    
    - `W` 키 추가 -> Modifiers에 **Swizzle Input Axis Values** 추가 (Y축 이동으로 변환)
        
    - `S` 키 추가 -> Modifiers에 **Swizzle Input Axis Values** 및 **Negate** 추가 (뒤로 이동)
        
    - `D` 키 추가 -> (기본 X축이므로 추가 모디파이어 없음, 우측 이동)
        
    - `A` 키 추가 -> Modifiers에 **Negate** 추가 (좌측 이동)
        
4. **IA_Look (마우스 회전)** 키 매핑:
    
    - `Mouse XY 2D-Axis`를 선택하여 등록합니다.
        
    - 마우스 상하 조작 시 화면이 뒤집히는 것을 방지하거나 취향에 맞게 조정하려면 **Negate**를 활용해 Y축(Pitch) 값을 반전시킬 수 있습니다.
        

## 3단계: C++ 입력 바인딩 및 활성화

### 1. 향상된 입력 모듈 등록

- C++에서 향상된 입력을 사용하려면 프로젝트의 `Build.cs` 파일 내 `PublicDependencyModuleNames` 배열에 `"EnhancedInput"` 문자열을 추가해야 합니다. (수정 후 프로젝트 리빌드 필수)
    

### 2. 함수 선언 및 IMC 참조 변수 만들기

- **헤더 파일**: 입력을 처리할 두 개의 함수를 선언합니다. 입력 값이 `Vector2D`이므로 매개변수로 `const FInputActionValue& Value`를 받도록 설계합니다.
    
    - `void Move(const FInputActionValue& Value);`
        
    - `void Look(const FInputActionValue& Value);`
        
- 에디터에서 기획한 IMC와 IA들을 C++ 코드와 연결할 수 있도록 `UInputMappingContext*`와 `UInputAction*` 타입의 변수들을 헤더에 선언하고 `UPROPERTY(EditAnywhere)`를 붙여줍니다.
    

### 3. SetupPlayerInputComponent()에서 바인딩

1. 소스 파일의 입력 설정 함수에서 기본 `InputComponent`를 `UEnhancedInputComponent`로 캐스팅(형변환)합니다.
    
2. 캐스팅에 성공하면 `BindAction()` 함수를 사용해 선언해 둔 `IA_Move`, `IA_Look` 액션과 방금 만든 `Move()`, `Look()` 처리 함수를 각각 연결(**Triggered** 상태일 때 발동하도록)합니다.
    

### 4. 컨트롤러 시점(BeginPlay)에서 IMC 등록

- Pawn이 게임에 배치되고 플레이어가 빙의(Possess)되었을 때 입력이 작동해야 하므로, `BeginPlay()` 함수 내에서 소유 중인 `PlayerController`를 가져옵니다.
    
- 컨트롤러의 `EnhancedInputLocalPlayerSubsystem`을 패치하여, C++ 변수로 받아온 `IMC_Pawn`을 시스템에 추가(`AddMappingContext`)합니다.
    

## 4단계: 이동 및 회전 로직 구현 (소스 파일 작업)

### 1. Move 함수 구현 (WASD 평면 이동)

1. 함수가 실행되면 매개변수(`Value`)로부터 `Vector2D` 타입의 입력 값을 추출합니다. (X는 좌우, Y는 전후 입력값)
    
2. **프레임 독립성 확보**: 입력 값에 `GetWorld()->GetDeltaSeconds()`를 곱하여 프레임률이 달라도 이동 속도가 일정하게 유지되도록 만듭니다. 여기에 원하는 이동 속도 상수(Speed)를 추가로 곱해줍니다.
    
3. **방향 계산**: 평면 상의 이동만 처리하므로, 현재 Pawn의 전방 벡터(`GetActorForwardVector()`)에 Y축 입력값을 곱하고, 우측 벡터(`GetActorRightVector()`)에 X축 입력값을 곱합니다.
    
4. **위치 반영**: 계산된 두 벡터를 더해 최종 이동 벡터를 만든 뒤, `AddActorLocalOffset()` 함수에 전달하여 Pawn을 이동시킵니다. (Sweeping을 켜서 충돌 처리가 되도록 설정할 수도 있습니다.)
    

### 2. Look 함수 구현 (마우스 회전)

1. 매개변수(`Value`)로부터 마우스의 X, Y 입력 값을 추출합니다. (X는 좌우 회전량, Y는 상하 회전량)
    
2. **Yaw(좌우 회전) 계산**: 마우스 X값에 회전 민감도(Sensitivity)와 `DeltaSeconds`를 곱해 이번 프레임에 회전할 각도를 계산합니다.
    
3. **Pitch(상하 회전) 계산**: 마우스 Y값에 민감도와 `DeltaSeconds`를 곱해 상하 각도를 계산합니다.
    
4. **회전 적용**: 엔진 제공 함수(`AddControllerYawInput` 등)를 쓰지 않아야 하므로, 계산된 Yaw와 Pitch 값을 이용해 `FRotator` 구조체를 생성합니다.
    
5. `AddActorLocalRotation()` 함수를 사용해 현재 액터에 회전 값을 직접 누적시킵니다. 평면 상의 회전과 카메라 시선 처리가 올바르게 작동하는지 확인합니다.
    

## 5단계: 블루프린트 생성 및 게임모드 설정

### 1. Pawn 블루프린트 클래스 생성

1. 에디터에서 방금 만든 C++ 클래스를 우클릭하고 Create Blueprint class based on...을 선택하여 블루프린트(예: `BP_MyPawn`)를 생성합니다.
    
2. 블루프린트를 열어 C++에서 만든 컴포넌트 계층 구조가 잘 들어와 있는지 확인합니다.
    
3. 디테일 패널에서 C++로 노출한 입력 변수 칸에 에디터에서 만든 `IMC_Pawn`, `IA_Move`, `IA_Look` 에셋을 각각 드롭다운으로 매핑해 줍니다.
    
4. 필요하다면 Skeletal Mesh 컴포넌트에 원하는 캐릭터 에셋을 지정합니다.
    

### 2. 게임모드(GameMode) 설정 및 테스트

1. 프로젝트에서 사용하는 **GameMode 블루프린트**를 생성하거나 기존 것을 엽니다.
    
2. 디테일 패널의 **Classes > Default Pawn Class** 항목을 찾아 방금 만든 C++ 기반 블루프린트인 `BP_MyPawn`으로 변경하고 저장합니다.
    
3. 게임을 시작(Play)하면 해당 Pawn이 자동으로 스폰되어 카메라 시점이 잡히며, WASD와 마우스로 물리 엔진의 간섭 없이 독립적인 이동/회전이 가능해집니다.

```cpp

#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Pawn.h"
#include "InputActionValue.h"
#include "BasePawn.generated.h"

class UCapsuleComponent;
class USkeletalMeshComponent;
class USpringArmComponent;
class UCameraComponent;
class UInputMappingContext;
class UInputAction;

UCLASS()
class STAGE01_API ABasePawn : public APawn
{
	GENERATED_BODY()

public:
	ABasePawn();

protected:
	virtual void BeginPlay() override;

public:
	virtual void Tick(float DeltaTime) override;
	virtual void SetupPlayerInputComponent(UInputComponent* PlayerInputComponent) override;

private:
	/* Components */

	UPROPERTY(VisibleAnywhere)
	UCapsuleComponent* CapsuleComp;

	UPROPERTY(VisibleAnywhere)
	USkeletalMeshComponent* MeshComp;

	UPROPERTY(VisibleAnywhere)
	USpringArmComponent* SpringArmComp;

	UPROPERTY(VisibleAnywhere)
	UCameraComponent* CameraComp;

	/* Input */

	UPROPERTY(EditAnywhere, Category = "Input")
	UInputMappingContext* IMC_Default;

	UPROPERTY(EditAnywhere, Category = "Input")
	UInputAction* IA_Move;

	UPROPERTY(EditAnywhere, Category = "Input")
	UInputAction* IA_Look;

	/* Movement */

	UPROPERTY(EditAnywhere, Category = "Movement")
	float MoveSpeed = 500.f;

	UPROPERTY(EditAnywhere, Category = "Movement")
	float RotationSpeed = 100.f;

	FVector2D MoveInput;
	FVector2D LookInput;

	/* Functions */

	void Move(const FInputActionValue& Value);
	void Look(const FInputActionValue& Value);
};

```

```cpp

#include "BasePawn.h"

#include "Camera/CameraComponent.h"
#include "Components/CapsuleComponent.h"
#include "Components/SkeletalMeshComponent.h"
#include "GameFramework/SpringArmComponent.h"

#include "EnhancedInputComponent.h"
#include "EnhancedInputSubsystems.h"

#include "InputAction.h"
#include "InputMappingContext.h"

ABasePawn::ABasePawn()
{
	PrimaryActorTick.bCanEverTick = true;

	// Capsule
	CapsuleComp =
		CreateDefaultSubobject<UCapsuleComponent>(TEXT("Capsule"));

	RootComponent = CapsuleComp;

	// Mesh
	MeshComp =
		CreateDefaultSubobject<USkeletalMeshComponent>(TEXT("Mesh"));

	MeshComp->SetupAttachment(RootComponent);

	// SpringArm
	SpringArmComp =
		CreateDefaultSubobject<USpringArmComponent>(TEXT("SpringArm"));

	SpringArmComp->SetupAttachment(RootComponent);
	SpringArmComp->TargetArmLength = 300.f;

	// Camera
	CameraComp =
		CreateDefaultSubobject<UCameraComponent>(TEXT("Camera"));

	CameraComp->SetupAttachment(SpringArmComp);

	// Physics Off
	CapsuleComp->SetSimulatePhysics(false);
	MeshComp->SetSimulatePhysics(false);
}

void ABasePawn::BeginPlay()
{
	Super::BeginPlay();

	if (APlayerController* PC = Cast<APlayerController>(GetController()))
	{
		if (ULocalPlayer* LocalPlayer = PC->GetLocalPlayer())
		{
			if (UEnhancedInputLocalPlayerSubsystem* Subsystem =
				LocalPlayer->GetSubsystem<UEnhancedInputLocalPlayerSubsystem>())
			{
				if (IMC_Default)
				{
					Subsystem->AddMappingContext(IMC_Default, 0);
				}
			}
		}
	}
}

void ABasePawn::Tick(float DeltaTime)
{
	Super::Tick(DeltaTime);

	// Move

	FVector MoveDelta =
		(GetActorForwardVector() * MoveInput.Y +
		 GetActorRightVector() * MoveInput.X)
		* MoveSpeed
		* DeltaTime;

	AddActorLocalOffset(MoveDelta, true);

	// Rotate

	FRotator RotationDelta;

	RotationDelta.Pitch = LookInput.Y * RotationSpeed * DeltaTime;
	RotationDelta.Yaw = LookInput.X * RotationSpeed * DeltaTime;

	AddActorLocalRotation(RotationDelta);
}

void ABasePawn::SetupPlayerInputComponent(UInputComponent* PlayerInputComponent)
{
	Super::SetupPlayerInputComponent(PlayerInputComponent);

	if (UEnhancedInputComponent* EIC =
		Cast<UEnhancedInputComponent>(PlayerInputComponent))
	{
		if (IA_Move)
		{
			EIC->BindAction(
				IA_Move,
				ETriggerEvent::Triggered,
				this,
				&ABasePawn::Move);
		}

		if (IA_Look)
		{
			EIC->BindAction(
				IA_Look,
				ETriggerEvent::Triggered,
				this,
				&ABasePawn::Look);
		}
	}
}

void ABasePawn::Move(const FInputActionValue& Value)
{
	MoveInput = Value.Get<FVector2D>();
}

void ABasePawn::Look(const FInputActionValue& Value)
{
	LookInput = Value.Get<FVector2D>();
}
```

폰 이동 문제?

작성하신 코드에서 발생한 문제의 원인은 "좌표계 변환의 중복 적용" 때문이었습니다.  
수학적으로 언리얼 엔진이 캐릭터의 위치를 계산하는 과정에서 똑같은 계산을 두 번 곱해버려, 화면을 돌릴 때 이동 방향이 기하급수적으로 틀어지게 된 것입니다. 이해하기 쉽게 개념부터 현상까지 자세히 정리해 드릴게요.  
1. 핵심 원인: 좌표계의 중복 계산  
언리얼 엔진에서 액터를 이동시키는 함수는 크게 두 가지가 있습니다.  

- `AddActorWorldOffset(벡터)`: 절대적인 월드 기준(북쪽, 동쪽, 하늘)으로 벡터만큼 움직입니다.
- `AddActorLocalOffset(벡터)`: 액터가 현재 바라보는 방향(로컬 기준)을 기준으로 벡터만큼 움직입니다. 함수 내부적으로 *'액터의 현재 회전 값'*을 곱해주는 연산이 들어있습니다. 작성하셨던 코드의 문제점 C++

// ❌ 문제가 발생한 코드
AddActorLocalOffset(GetActorForwardVector() * MoveInput.X * MoveSpeed * DeltaTime);

1. `GetActorForwardVector()`: 이 함수는 이미 캐릭터의 회전 상태가 반영된 '월드 기준의 앞방향 벡터'를 반환합니다. (예: 캐릭터가 45도 회전해 있다면`(0.7, 0.7, 0)`같은 값이 나옵니다.)
2. `AddActorLocalOffset()`: 이 함수는 입력받은 벡터를 캐릭터의 회전 값만큼 한 번 더 회전시킵니다.
3. 결과: 캐릭터의 회전(Rotation) 값이 방향 계산에 두 번(제곱으로) 적용되었습니다.
4. 이로 인해 나타난 구체적 현상 (왜 ![:오른쪽_아래를_향한_화살표:](https://a.slack-edge.com/production-standard-emoji-assets/16.0/google-medium/2198-fe0f@2x.png) 방향으로 갔을까?)
5. 가만히 앞만 보고 갈 때는 회전 값이 `0`에 가깝기 때문에 정상적으로 움직이는 것처럼 느껴집니다. 하지만 마우스를 돌리는 순간 문제가 터집니다.
6. 내가 의도한 상황: 마우스를 오른쪽으로 45도 돌리고 W를 누르면, 내 눈앞(![:오른쪽_위를_향한_화살표:](https://a.slack-edge.com/production-standard-emoji-assets/16.0/google-medium/2197-fe0f@2x.png)) 방향으로 캐릭터가 가길 원함.
7. 실제 일어난 계산 (예시): 1. 마우스를 45도 돌렸으니`GetActorForwardVector()`가 오른쪽 45도(![:오른쪽_위를_향한_화살표:](https://a.slack-edge.com/production-standard-emoji-assets/16.0/google-medium/2197-fe0f@2x.png))를 가리킵니다. 2. 이 값을`AddActorLocalOffset`에 넣었습니다. 3. 함수 내부에서 "아, 현재 캐릭터가 45도 돌아가 있네? 입력받은 벡터를 오른쪽으로 45도 더 돌려야지!" 하고 계산해 버립니다. 4. 결국 45도(![:오른쪽_위를_향한_화살표:](https://a.slack-edge.com/production-standard-emoji-assets/16.0/google-medium/2197-fe0f@2x.png))에서 45도가 더 돌아간 90도(오른쪽 완전 옆방향 ![:오른쪽_화살표:](https://a.slack-edge.com/production-standard-emoji-assets/16.0/google-medium/27a1-fe0f@2x.png)) 혹은 각도가 더 커져 동남쪽(![:오른쪽_아래를_향한_화살표:](https://a.slack-edge.com/production-standard-emoji-assets/16.0/google-medium/2198-fe0f@2x.png))으로 캐릭터가 미끄러지듯 날아가 버린 것입니다. 이 때문에 마우스를 조금만 돌려도 캐릭터가 과하게 회전한 것처럼 엉뚱한 방향으로 튕겨 나가는 현상이 발생했습니다.
8. 올바른 해결 공식
9. 6자유도(6 DOF) 비행체처럼 내 캐릭터의 로컬 좌표계를 기준으로 움직이게 하려면 두 가지 방법 중 하나만 선택해서 명확하게 기준을 세워야 합니다.
10. 방법 A: Local 함수 + 순수 축 벡터 (추천 ![:흰색_확인_표시:](https://a.slack-edge.com/production-standard-emoji-assets/16.0/google-medium/2705@2x.png))
11. 함수 자체에 회전 계산이 들어있으므로, 인자로는 순수한 로컬 축(앞은 X, 우측은 Y, 위는 Z)만 넘겨줍니다. 과제 요구사항인 'Local 기반 이동'에 가장 완벽히 부합하는 방식입니다.
12. 앞(W):`AddActorLocalOffset(FVector(1, 0, 0) * ...)`
13. 오른쪽(D):`AddActorLocalOffset(FVector(0, 1, 0) * ...)`
14. 위(Space): `AddActorLocalOffset(FVector(0, 0, 1) * ...)`
15. 방법 B: World 함수 + 방향 벡터
16. 내가 방향 벡터를 직접 구해서 적용하고 싶다면, 중복 계산을 하지 않는 월드 기준 함수를 써야 합니다.
17. 앞(W):`AddActorWorldOffset(GetActorForwardVector() * ...)`
18. 오른쪽(D):`AddActorWorldOffset(GetActorRightVector() * ...)`
19. 위(Space):`AddActorWorldOffset(GetActorUpVector() * ...)`요약하자면,`AddActorLocalOffset`이라는 로컬 이동 함수를 사용하시면서 벡터까지`GetActorForwardVector`(월드 방향 벡터)를 중복으로 곱해주었기 때문에 각도가 제곱으로 계산되어 캐릭터가 이상하게 움직였던 것입니다!

```cpp
void ABasePawn::SetupPlayerInputComponent(UInputComponent* PlayerInputComponent)
{
    Super::SetupPlayerInputComponent(PlayerInputComponent);

    if (UEnhancedInputComponent* EnhancedInput = Cast<UEnhancedInputComponent>(PlayerInputComponent))
    {
        if (ASpartaPlayerController* PlayerController = Cast<ASpartaPlayerController>(GetController()))
        {
            // 1. WASD 평면 이동 바인딩
            if (PlayerController->MoveAction)
            {
                EnhancedInput->BindAction(PlayerController->MoveAction, ETriggerEvent::Triggered, this, &ABasePawn::Move);
            }
            
            // 2. 마우스 시선 전환 바인딩
            if (PlayerController->LookAction)
            {
                EnhancedInput->BindAction(PlayerController->LookAction, ETriggerEvent::Triggered, this, &ABasePawn::Look);
            }
            
            // 3. 위/아래 수직 이동 바인딩 (Q/E)
            if (PlayerController->UpMoveAction)
            {
                EnhancedInput->BindAction(PlayerController->UpMoveAction, ETriggerEvent::Triggered, this, &ABasePawn::FlyUpDown);
            }
        }
    }
}

// 1. 평면 이동 (WASD 입력 처리)
void ABasePawn::Move(const FInputActionValue& Value)
{
    if (!Controller) return;

    // Enhanced Input에서 Vector2D 축 값을 가져옵니다.
    const FVector2D MoveInput = Value.Get<FVector2D>();

    // 앞 / 뒤 이동
    if (!FMath::IsNearlyZero(MoveInput.X))
    {
        // 노션 표준: 폰이 바라보는 앞방향(Forward) 벡터를 기준으로 입력 축 값을 전달
        AddMovementInput(GetActorForwardVector(), MoveInput.X);
    }

    // 좌 / 우 이동
    if (!FMath::IsNearlyZero(MoveInput.Y))
    {
        // 노션 표준: 폰의 오른쪽(Right) 벡터를 기준으로 입력 축 값을 전달
        AddMovementInput(GetActorRightVector(), MoveInput.Y);
    }
}

// 2. 시선 전환 (마우스 회전 처리)
void ABasePawn::Look(const FInputActionValue& Value)
{
    const FVector2D LookInput = Value.Get<FVector2D>();

    AddControllerYawInput(LookInput.X);   // 마우스 좌우 -> 폰 회전
    AddControllerPitchInput(LookInput.Y); // 마우스 상하 -> 카메라 시선 회전
}

// 3. 위/아래 수직 비행 (IA_UpMove 입력 처리)
void ABasePawn::FlyUpDown(const FInputActionValue& Value)
{
    // 수직 이동은 1D Axis(float) 값이므로 float으로 가져옵니다.
    const float VerticalValue = Value.Get<float>();

    if (!FMath::IsNearlyZero(VerticalValue))
    {
        // [수정 완료] 노션 스타일로 변경: 
        // 월드 기준 수직 위 방향(Z축)인 FVector::UpVector를 활용해 입력을 전달합니다.
        AddMovementInput(FVector::UpVector, VerticalValue);
    }
}
```

```cpp
    void Look(const FInputActionValue& Value); // 마우스 회전 등 시선 이동 입력이 들어왔을 때 실행될 함수입니다.

    UFUNCTION()
    void FlyUpDown(const FInputActionValue& Value); // 위/아래 플라잉(상승/하강) 입력이 들어왔을 때 실행될 함수입니다.
};
```

```cpp
// 플레이어의 입력 장치(키보드/마우스 등)와 C++ 함수를 연결해주는 함수입니다.
void ABasePawn::SetupPlayerInputComponent(UInputComponent* PlayerInputComponent)
{
    // 부모 클래스(APawn)의 기본 입력 설정 함수를 먼저 실행합니다.
    Super::SetupPlayerInputComponent(PlayerInputComponent);
    
    // 들어온 기본 입력 컴포넌트(PlayerInputComponent)를 UE5용 '향상된 입력 컴포넌트(UEnhancedInputComponent)'로 캐스팅(형변환) 검사합니다.
    if (UEnhancedInputComponent* EnhancedInput = Cast<UEnhancedInputComponent>(PlayerInputComponent))
    {
        // 현재 이 폰을 조종하고 있는 컨트롤러를 우리가 만든 커스텀 'ASpartaPlayerController' 클래스로 캐스팅(형변환) 검사합니다.
        if (ASpartaPlayerController* PlayerController = Cast<ASpartaPlayerController>(GetController()))
        {
            // 1. WASD 평면 이동 바인딩
            // 컨트롤러에 MoveAction(입력 에셋)이 정상적으로 등록되어 있는지 확인합니다.
            if (PlayerController->MoveAction)
            {
                // MoveAction이 입력되는 중(Triggered)일 때, 이 클래스(this)의 Move 함수를 실행하도록 연결합니다.
                EnhancedInput->BindAction(PlayerController->MoveAction, ETriggerEvent::Triggered, this, &ABasePawn::Move);
            }
            
            // 2. 마우스 시선 전환 바인딩
            // 컨트롤러에 LookAction이 정상적으로 등록되어 있는지 확인합니다.
            if (PlayerController->LookAction)
            {
                // LookAction이 입력되는 중(Triggered)일 때, 이 클래스(this)의 Look 함수를 실행하도록 연결합니다.
                EnhancedInput->BindAction(PlayerController->LookAction, ETriggerEvent::Triggered, this, &ABasePawn::Look);
            }
            
            // 3. 위/아래 수직 이동 바인딩 (Q/E 등)
            // 컨트롤러에 UpMoveAction이 정상적으로 등록되어 있는지 확인합니다.
            if (PlayerController->UpMoveAction)
            {
                // UpMoveAction이 입력되는 중(Triggered)일 때, 이 클래스(this)의 FlyUpDown 함수를 실행하도록 연결합니다.
                EnhancedInput->BindAction(PlayerController->UpMoveAction, ETriggerEvent::Triggered, this, &ABasePawn::FlyUpDown);
            }
        }
    }
}

// 1. 평면 이동 (WASD 입력 처리)
void ABasePawn::Move(const FInputActionValue& Value)
{
    // 이 폰을 제어하는 컨트롤러가 없다면(빙의되지 않은 상태라면) 함수를 즉시 종료합니다.
    if (!Controller) return;
    
    // 입력된 데이터를 2D 벡터(X축: 앞뒤, Y축: 좌우) 형태로 변환하여 가져옵니다.
    const FVector2D MoveInput = Value.Get<FVector2D>();

    // 앞 / 뒤 이동 처리
    // 입력받은 X축 값이 거의 0이 아니라면 (실제 키보드 W나 S를 눌렀다면)
    if (!FMath::IsNearlyZero(MoveInput.X))
    {
        // 폰이 현재 바라보고 있는 기준 앞방향 벡터(Forward)를 구하고, 입력값(MoveInput.X) 만큼 이동 입력을 가합니다.
        AddMovementInput(GetActorForwardVector(), MoveInput.X);
    }

    // 좌 / 우 이동 처리
    // 입력받은 Y축 값이 거의 0이 아니라면 (실제 키보드 A나 D를 눌렀다면)
    if (!FMath::IsNearlyZero(MoveInput.Y))
    {
        // 폰의 현재 기준 오른쪽 방향 벡터(Right)를 구하고, 입력값(MoveInput.Y) 만큼 이동 입력을 가합니다.
        AddMovementInput(GetActorRightVector(), MoveInput.Y);
    }
}

// 2. 시선 전환 (마우스 회전 처리)
void ABasePawn::Look(const FInputActionValue& Value)
{
    // 마우스의 움직임 값을 2D 벡터(X: 좌우 움직임, Y: 상하 움직임) 형태로 가져옵니다.
    const FVector2D LookInput = Value.Get<FVector2D>();
    
    // 마우스 좌우 입력값(LookInput.X)을 사용해 플레이어 컨트롤러의 Yaw(좌우 회전 값)를 회전시킵니다. (폰 자체가 좌우로 회전하게 됨)
    AddControllerYawInput(LookInput.X);   
    
    // 마우스 상하 입력값(LookInput.Y)을 사용해 플레이어 컨트롤러의 Pitch(상하 회전 값)를 회전시킵니다. (카메라 시선이 위아래로 움직이게 됨)
    AddControllerPitchInput(LookInput.Y); 
}

// 3. 위/아래 수직 비행 (Q/E 등의 입력 처리)
void ABasePawn::FlyUpDown(const FInputActionValue& Value)
{
    // 수직 이동은 단일 축(1D Axis) 데이터이므로 실수(float) 형태로 변환하여 값을 가져옵니다.
    const float VerticalValue = Value.Get<float>();
    
    // 입력받은 수직 값이 거의 0이 아니라면 (위나 아래로 움직이라는 키를 눌렀다면)
    if (!FMath::IsNearlyZero(VerticalValue))
    {
        // 월드(세계)의 절대적인 하늘 방향 벡터인 Z축(FVector::UpVector, 즉 (0,0,1))을 기준으로 입력값만큼 수직 상승/하강 입력을 가합니다.
        AddMovementInput(FVector::UpVector, VerticalValue);
    }
}
```

발생할 수 있는 문제

제공해주신 코드는 기본적인 구조를 아주 잘 갖추고 있지만, 언리얼 엔진의 `APawn`과 **향상된 입력(Enhanced Input)**, 그리고 컴포넌트의 물리적 특성 때문에 실제로 플레이해보면 세 가지 주요 문제(또는 버그처럼 보이는 현상)를 마주하게 됩니다.

구현하신 폰(Pawn)을 에디터에 배치하고 테스트할 때 발생할 수 있는 잠재적 문제점과 해결 방법을 정리해 드립니다.

## 1. 폰(Pawn)이 움직이지 않는 문제 (가장 흔함)

`APawn` 클래스는 `ACharacter` 클래스와 달리 **기본적인 이동 로직(Movement Component)이 내장되어 있지 않습니다.** * **원인:** 코드에서 `AddMovementInput` 함수를 호출하고 있지만, 이 입력값을 받아서 실제로 폰을 물리적으로 물리치거나 이동시켜 줄 'Movement Component'가 이 클래스에는 존재하지 않습니다.

- **증상:** 키보드를 눌러도 폰이 꿈쩍도 하지 않습니다.
    
- **해결 방법:** 1. 헤더 파일에 `UPawnMovementComponent`를 상속받은 컴포넌트(예: `UFloatingPawnMovement`)를 추가하고 생성자에서 생성해 주어야 합니다.
    
    2. 혹은, 비행/부유하는 캐릭터가 아니라면 부모 클래스를 `APawn` 대신 처음부터 이동 컴포넌트가 내장된 `ACharacter`로 변경하는 것이 좋습니다.
    

## 2. 수직 비행(`FlyUpDown`) 시 폰이 바닥에 박히거나 무한 상승하는 문제

현재 수직 이동 방향을 월드의 절대 위 방향(`FVector::UpVector`)으로 설정해 두셨습니다.

- **원인:** 만약 중력(Gravity)이 적용되는 상태라면, 수직 위로 가려고 해도 중력 때문에 올라가지 못하거나 뚝뚝 끊길 수 있습니다. 반대로 중력이 없다면 Q나 E를 눌렀을 때 마찰력 없이 우주 공간처럼 무한히 상승/하강하게 됩니다.
    
- **증상:** 바닥 콜리전(충돌체)에 걸려 위로 안 올라가거나, 한 번 누르면 멈추지 않고 계속 날아갑니다.
    
- **해결 방법:** 이동 컴포넌트(Movement Component)의 세팅에서 `Gravity Scale`을 0으로 만들어 구현하려는 '비행 폰'의 컨셉에 맞추거나, `Max Fly Speed`와 제동력(Deceleration) 설정을 조정해야 합니다.
    

## 3. 카메라 회전(Look) 시 화면이 떨리거나 원하지 않는 방향으로 도는 현상

생성자에서 스프링암과 카메라의 회전 옵션을 아래와 같이 주셨습니다.

- `SpringArmComp->bUsePawnControlRotation = true;` (컨트롤러 따라 스프링암 회전)
    
- `CameraComp->bUsePawnControlRotation = false;` (카메라는 스프링암을 따름)
    
- **원인:** 마우스를 위아래(Pitch)로 움직이면 스프링암이 회전하면서 카메라 시선이 위아래로 잘 움직입니다. 하지만 마우스를 좌우(Yaw)로 움직이면 `Look` 함수 내부의 `AddControllerYawInput`에 의해 **폰(Pawn) 본체 자체가 회전**하게 됩니다. 폰이 회전하면 폰의 자식인 스프링암도 같이 회전하므로 이중으로 계산되거나 시선이 꼬일 수 있습니다.
    
- **증상:** 마우스를 좌우로 돌릴 때 카메라가 부드럽게 돌지 않고 메쉬와 함께 부자연스럽게 회전하거나 화면이 미세하게 떨릴 수 있습니다.
    
- **해결 방법:** 일반적으로 3인칭 게임에서는 폰 자체는 가만히 있고 카메만 돌다가, 이동할 때 이동 방향으로 메쉬가 회전하도록 설정합니다. 이를 위해서는 `APawn` 고유의 회전 세팅(`bUseControllerRotationYaw = false;` 등)을 생성자에서 명확하게 제어해 주어야 합니다.
    

## 4. 빌드 에러 및 크래시 위험 (코드 상의 사소한 실수)

주신 .cpp 코드 중 컴포넌트 생성 부분에 오타가 하나 있습니다.

C++

```
// 기존 코드
SpringArmComp = SetupAttachment(RootComponent); 

// 올바른 코드
SpringArmComp->SetupAttachment(RootComponent); // 화살표(->) 누락
```

이 부분 때문에 컴파일 에러(빌드 실패)가 발생합니다. `->` 기호로 수정해 주셔야 합니다.
