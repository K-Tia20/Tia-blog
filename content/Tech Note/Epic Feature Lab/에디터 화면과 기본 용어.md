

이 자료는 `EpicFeatureLab`을 만들면서 남긴 제작 기록이다. 제작 기록 20편과 이 기본 안내 1편으로 구성했다. 1–18편은 실제로 만든 기능, 19편은 이 프로젝트에서 실행하지 못한 기술의 확인 기록, 20편은 모든 실험을 하나의 실행 파일로 묶은 과정이다.

처음부터 모든 코드를 읽을 필요는 없다. **프로젝트를 열고 → 글에 적힌 장면을 찾고 → 값을 하나 바꾸고 → 결과를 본 뒤 → 원래대로 돌리는 순서**로 시작하면 된다. 각 글 중간의 제작 과정은 그 장면이 어떤 재료와 연결로 만들어졌는지 설명한다. 마지막의 소스 파일은 그 과정을 구현한 전체 코드다.

## 먼저 알아둘 다섯 가지

| 화면에 나오는 말 | 여기서는 이렇게 이해하면 된다 |
|---|---|
| 프로젝트 | 게임에 쓰는 장면, 캐릭터, 코드, 설정을 모은 작업 폴더. 이 프로젝트를 여는 파일은 `EpicFeatureLab.uproject`다. |
| 에셋(Asset) | 언리얼에서 사용하는 재료 파일. 캐릭터, 재질, 애니메이션, 소리와 노드 그래프도 에셋이다. |
| 레벨·맵(Level·Map) | 물건과 조명, 캐릭터를 배치한 하나의 장면. 이 글에서는 거의 같은 뜻으로 쓴다. |
| 액터(Actor) | 장면에 놓인 물건 한 개. 같은 의자 에셋을 장면에 세 번 놓으면 의자 액터가 세 개 생긴다. |
| 컴포넌트(Component) | 액터에 붙은 부품. 캐릭터 하나에 몸 메시, 카메라, 충돌 부품이 함께 들어갈 수 있다. |

`/Game/FeatureLab/Maps`처럼 적힌 경로는 웹 주소가 아니다. **콘텐츠 브라우저 안에서 찾을 폴더 위치**다. 맨 앞 `/Game`은 프로젝트의 `Content` 폴더를 가리킨다. 따라서 `/Game/FeatureLab/Maps`는 탐색기의 `Content/FeatureLab/Maps`와 대응한다.

## 에디터 화면을 읽는 순서

에디터는 언리얼의 작업 프로그램이다. 실행 파일로 게임만 보는 것과 달리, 재료를 열고 고칠 수 있다.

1. **가운데 뷰포트(Viewport)**: 장면을 보는 창이다. 여기서 캐릭터와 조명, 배치 결과를 본다.
2. **아래 콘텐츠 브라우저(Content Browser)**: 에셋을 찾는 창이다. 아래 `Content Drawer` 버튼이나 `Window → Content Browser`로 연다.
3. **오른쪽 아웃라이너(Outliner)**: 현재 장면에 놓인 액터 목록이다. 폴더 안의 원본 에셋 목록과 다르다.
4. **오른쪽 디테일(Details)**: 선택한 액터나 에셋의 설정 창이다. 다른 것을 선택하면 여기 보이는 항목도 바뀐다.
5. **위쪽 초록색 ▶ Play**: 장면을 실제로 실행한다. 실행하면 ■ Stop 버튼이 활성화된다. 물건을 편집할 때는 먼저 Stop을 누른다.

사진에 화면 전체가 작게 보이면 원본 이미지를 새 탭으로 열어 확대한다. 숫자와 테두리를 붙인 사진은 클릭 위치를 설명하기 위한 편집본이고, `-original` 이름의 이미지는 원본 캡처다.

## 내 컴퓨터에서 첫 장면 열기

화면과 파일명은 작업 당시 만든 `EpicFeatureLab` 프로젝트의 예다. 자기 프로젝트에서는 같은 종류의 에셋과 설정을 찾아 적용한다. 메타휴먼 데이터, 공식 샘플과 플러그인은 각 제작 글의 준비 사항을 먼저 확인한다.

1. Epic Games Launcher에서 `Unreal Engine → Library`를 연다. 이번 기록은 **UE 5.8.4** 기준이다.
2. 탐색기에서 `EpicFeatureLab.uproject`를 더블클릭한다. 엔진 버전 선택 창이 나타나면 작업에 사용한 5.8 엔진을 선택한다.
3. 처음 열 때 셰이더를 준비하는 시간이 필요할 수 있다. 셰이더는 재질과 조명을 화면에 그리기 위한 GPU 프로그램이다. 로딩 중에 버튼을 반복해서 누르지 않는다.
4. 콘텐츠 브라우저에서 `Content → FeatureLab → Maps`를 차례로 연다.
5. `FL_Hub`를 더블클릭한다. 위쪽 ▶ Play를 누른다.
6. 한국어 실험 목록에서 원하는 번호를 누른다. **F10**으로 목록을 다시 연다.
7. 키가 먹지 않으면 먼저 게임이 보이는 영역을 한 번 클릭한다. 키보드 입력을 받을 창에 초점이 가야 한다.
8. 편집기로 돌아와 값을 고치려면 ■ Stop을 누른다. 게임 실행 중 바꾼 값과 원본 에셋에 저장한 값은 별개다.

완성 화면만 보고 싶다면 `Builds/WindowsFeatureLab/EpicFeatureLab.exe`를 연다. 실행 파일 하나만 다른 폴더로 옮기면 안 된다. 옆의 콘텐츠와 실행 지원 파일이 필요하므로 `WindowsFeatureLab` 폴더 전체가 한 묶음이다.

## 코드를 모르는 상태에서 노드 그래프 읽기

블루프린트는 상자를 선으로 연결해서 동작을 만드는 방식이다. **노드**는 상자, **핀**은 상자의 입출력 단자, **와이어**는 두 단자를 연결한 선이다. 숫자를 넣는 핀, 물건을 지정하는 핀, 실행 순서를 전달하는 핀이 따로 있다.

이 프로젝트의 모든 그래프가 블루프린트인 것은 아니다. `CR_`로 시작하는 Control Rig는 뼈와 표정 제어, `PCG_`는 배치 생성, `DF_` 또는 의상 Dataflow는 천 제작 데이터, `MRG_`는 영상 출력 순서를 다룬다. 모양은 비슷하지만 서로 다른 편집기다. 엉뚱한 그래프 창에서 같은 이름의 노드를 찾지 않도록 글마다 **열어야 할 에셋 이름**을 적었다.

`Compile`은 현재 연결과 코드가 실행 가능한지 준비하는 작업이다. `Save`는 그 결과를 파일에 남기는 작업이다. 저장했다고 잘못된 연결이 자동으로 고쳐지지는 않는다. 반대로 컴파일이 성공했어도 저장하지 않으면 다음에 열었을 때 수정 사항이 없을 수 있다.

## 원본을 두고 연습하는 방법

완성 프로젝트에서 먼저 결과를 확인한다. 그다음 값을 바꿔 보려면 콘텐츠 브라우저에서 해당 에셋을 **우클릭 → Duplicate(복제)** 하고 이름 끝에 `_Practice`를 붙인다. 노드 그래프가 다른 에셋을 참조하면 복제본도 원본을 계속 참조할 수 있다. 디테일의 연결 대상을 확인하고, 원본 캐릭터나 원본 재질까지 같이 바꾸지 않았는지 살핀다.

각 글 아래의 Python 코드에는 최초 생성, 진단, 결과 측정, 복구용 스크립트가 함께 있다. **폴더 안의 파일을 한꺼번에 실행하는 방식으로 사용하지 않는다.** 같은 이름의 에셋을 만들거나 실험 상태를 바꾸는 파일이 있다. 글에 나온 파일의 역할을 읽고, 다시 제작할 때는 복사한 프로젝트에서 순서대로 사용한다.

Python은 에디터의 반복 작업을 실행한 언어이고, C++는 실행 중 동작을 만든 언어다. `.py`, `.cpp`, `.h`는 메모장으로도 읽을 수 있는 텍스트 파일이다. `.uasset`은 언리얼 전용 작업 파일이므로 언리얼에서 연다. `.uasset`을 메모장에 붙여 넣어서 그래프를 만드는 방식은 아니다.

## 이 시리즈의 범위

1–18번의 35개 기능은 실제 제작과 개별 검증을 거쳤다. 19번의 UE6·Verse·Scene Graph는 이 UE 5.8 프로젝트에서 실행하지 않았다. RealityScan과 전신 마커리스 모캡도 이번 제작 범위에서 제외했다. 제외한 기능을 다른 장면이나 설명 그림으로 대신해 구현했다고 쓰지 않았다.

사진은 실제 에디터·실행 화면이다. 비교 GIF는 캡션에 비교라고 표시하고, 실제로 연속 촬영하거나 렌더링한 GIF와 구분한다. 코드와 측정 수치는 이 프로젝트에서 확인한 결과다. 다른 PC의 성능이나 다른 엔진 버전까지 같은 결과를 보장하는 숫자로 읽지 않으면 된다.

## 각 기술 글을 시작하기 전에

1. 글에 적힌 엔진 버전과 사용할 플러그인을 확인한다. 이 시리즈의 실제 제작 환경은 UE 5.8.4다.
2. 필요한 공식 샘플과 Fab 에셋을 각 공식 출처에서 준비한다. 사진 속 파일명은 제작 기록에서 붙인 이름이다.
3. 설명에 나온 에셋 종류부터 확인한다. 캐릭터 Blueprint, MetaHuman Character, Control Rig는 서로 다른 작업 파일이다.
4. 제작 중인 프로젝트의 사본에서 값을 하나씩 바꾼다. Play 중의 임시 변경과 에셋에 저장한 변경을 구분한다.
5. 각 글 아래의 코드는 파일명별로 나뉜다. 해당 이름으로 저장하고, 첫머리 주석의 입력 경로와 선행 조건을 자기 프로젝트에 맞춘다.

<a id="code-reading"></a>

## 코드가 처음이라면 읽는 순서

함수는 이름을 붙인 작업 묶음이다. 먼저 파일 맨 위의 역할 설명을 읽고, `/Game/` 경로가 어떤 에셋을 가리키는지 확인한다. 다음으로 값을 정하는 부분과 그 값을 실제 캐릭터·리그·장면에 전달하는 부분을 이어서 읽는다. 마지막으로 결과 검사와 저장 부분을 확인한다.

| 표시 | 쉬운 뜻 |
|---|---|
| Python의 `#`, C++의 `//` | 사람을 위한 주석. 실행하지 않는 설명이다. |
| `if` | 조건에 맞을 때만 실행한다. |
| `for` | 목록의 항목마다 같은 작업을 반복한다. |
| `def`, 함수 이름 | 여러 동작을 한 작업으로 묶는다. 정의와 실제 호출은 다르다. |
| `return` | 결과를 돌려주고 현재 함수를 끝낸다. |
| `assert` | 반드시 맞아야 하는 조건을 확인한다. 입력 조건을 먼저 살핀다. |
| `.py` | Python 코드 파일. `import unreal`이 있으면 언리얼 에디터의 Python 환경을 사용한다. |
| `.h` | C++에서 제공하는 객체·변수·함수를 선언한다. |
| `.cpp` | C++의 실제 동작을 구현한다. 언리얼 프로젝트에 포함해 빌드한다. |
| `.cs` | 언리얼의 모듈과 빌드 대상을 정하는 C# 빌드 규칙이다. |
| `.ps1` | Windows PowerShell 스크립트다. 파일 첫머리에 적힌 실행 환경을 확인한다. |

코드에 기록된 드라이브와 프로젝트 경로는 제작한 PC의 값이다. 자기 경로로 바꾸되, 존재 여부를 확인하는 검사 자체를 지우지는 않는다. 최초 제작, 중간 수정, 검사 스크립트는 역할이 다르므로 파일명 순서대로 한꺼번에 실행하지 않는다.

## 그래프에서 상자와 선이 뜻하는 것

노드는 작업을 나타내는 상자이고, 핀은 값을 받거나 내보내는 단자다. 와이어는 핀끼리 값을 전달하거나 실행 순서를 잇는 선이다. 글의 그래프 표에는 노드 이름, 핀의 값, 연결을 기록했고, 이어지는 `text` 블록에는 실제 전체 그래프 텍스트를 넣었다.

Control Rig는 뼈와 표정을, PCG는 배치를, 의상 Dataflow는 천 제작 데이터를, Movie Render Graph는 영상 출력 절차를 다룬다. 모양이 비슷하더라도 서로 다른 편집기이므로 먼저 글에 적힌 에셋 종류를 확인한다. 바이너리 `.uasset` 파일은 코드 블록을 메모장으로 저장해서 대신 만들 수 없다.
