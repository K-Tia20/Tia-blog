💡 오늘 배운 핵심 지식 (Today I Learned)

1. UI의 컴포넌트화 (HUD 편입 아키텍처)

  • 문제: 상호작용 팝업, 알림창, 보스 체력바 등을 필요할 때마다 Create Widget으로 허공에 생성하고 지우면 성능(오버헤드) 낭비가 발생하고 레이아웃 관리가 어렵다.
  • 해결: WBP_HUD라는 거대한 메인 캔버스 안에 자잘한 팝업 위젯들을 부품처럼 미리 배치(편입) 해둔다! 기본 상태를 Hidden(숨김)으로 해두고, 필요할 때만 메인 HUD의 이벤트를 통해 해당 부품의 Visibility를 Visible(보임)로 켜주는 방식이 정석이자 최고의 아키텍처임을 깨달았다.

2. 블루프린트 방어 로직 (스팸 호출 필터링)

  • 상황: 백엔드(C++)에서 타이머 로직과 묶이는 바람에, 0.1초마다 UpdateWaveText 이벤트가 미친 듯이 호출(스팸)되는 버그가 발생했다. 이로 인해 애니메이션이 0.1초마다 리셋되어 화면에 멈춰있는 현상이 일어났다.
  • 해결: 블루프린트 내부에 Old Wave 라는 변수를 하나 만들고, Branch 노드를 사용해 **“새로 들어온 숫자(Current Wave)가 이전 숫자와 다를(!=) 때만 통과시킨다”**는 강력한 방어막을 구축했다. True일 때만 Old Wave를 덮어쓰기(Set)하고 애니메이션을 틀어줌으로써 백엔드의 결함을 UI 측에서 완벽하게 커버해 냈다!

3. 하얀 선(실행선)의 절대적인 규칙

  • 변수를 꺼내고 데이터 선(파란색, 분홍색 등)을 아무리 완벽하게 꽂아두어도, 하얀색 실행선이 해당 노드를 관통하지 않고 건너뛰면 그 코드는 절대 실행되지 않는다. (전기가 안 통하는 가전제품과 같다!)

4. 화면 전환(Open Level)과 Z-Order의 이해

  • Open Level 노드가 실행되면 기존 맵의 모든 액터와 UI가 즉시 파괴된다. 따라서 부드러운 로딩 연출을 하려면 [구 맵에서 FadeOut ➡️ 레벨 이동 ➡️ 신 맵에서 FadeIn] 순서로 역할을 분담해야 한다.
  • 위젯끼리 겹쳤을 때 누가 앞에 보일지는 **Z-Order**가 결정한다. 로딩창처럼 모든 걸 덮어야 하는 UI는 Add to Viewport 시 Z-Order 값을 100 이상으로 넉넉하게 주면 메인 HUD를 완벽히 가릴 수 있다.

5. 깃허브(GitHub) PR 자동 닫힘 (Auto-close)

  • PR 본문에 Resolves #이슈번호를 적으면 PR이 Merge될 때 이슈가 자동으로 닫힌다.
  • 단, 이 기능은 깃허브 설정의 **[Default Branch]**로 Merge될 때만 작동하므로, develop 브랜치를 메인으로 쓴다면 Settings ➡️ General에서 Default Branch를 develop으로 명시해 주어야 한다.
  • 하지만 무서우니까 그냥 수동 체크 하겠다.

1. 웨이브 알림 애니메이션 재생 불가 현상 (스팸 호출 필터링)

  • 문제 (Problem): 새 웨이브가 시작될 때 중앙 알림창(WBP_WaveAnnouncer)이 나타나며 크기가 커지는 애니메이션이 재생되어야 함.
  • 오류 (Error): 애니메이션이 0.0초 구간에서 리셋을 반복하며, 크기가 변하지 않고 화면에 그대로 멈춰있는 현상 발생.
  • 원인 (Cause): 백엔드(C++)의 타이머 로직이 0.1초마다 UpdateWaveText 이벤트를 반복 호출하여, 애니메이션이 채 재생되기도 전에 계속 처음부터 재시작(Reset)되는 로직 결함이 있었음.
  • 해결 (Solution): 블루프린트 내부에 Old Wave 라는 변수와 Branch (조건문) 노드를 추가하여 방어 로직을 구축. “새로 들어온 웨이브 숫자”가 “이전 숫자”와 다를(!=) 때만 Old Wave를 갱신(Set)하고 애니메이션을 1회만 재생하도록 필터링하여 스팸 호출 버그를 완벽하게 차단함.

2. 블루프린트 텍스트 갱신 실패 (실행선 누락)

  • 문제 (Problem): 팝업 위젯이나 알림창에서 프로그래머가 넘겨준 텍스트(예: “WAVE 1”, “F를 누르세요”)로 글자가 바뀌어야 함.
  • 오류 (Error): C++에서 데이터를 제대로 쐈음에도 화면에 기본 텍스트만 출력되고 글자가 바뀌지 않음.
  • 원인 (Cause): 데이터 핀(분홍색, 파란색 선)은 정상적으로 연결되었으나, 노드의 실제 작동을 제어하는 **하얀색 실행선(Execution Pin)**이 SetText 노드를 거치지 않고 곧바로 Set Visibility 노드로 건너뛰어 연결되어 있었음. (전력이 공급되지 않는 상태)
  • 해결 (Solution): 하얀 실행선의 흐름을 끊고 이벤트 시작 ➡️ SetText ➡️ Set Visibility ➡️ Play Animation 순서로 직렬 연결되도록 흐름을 재배치하여 데이터 갱신과 화면 연출이 순서대로 작동하게 수정함.

3. 로딩 화면과 메인 HUD 겹침 현상 (Z-Order 제어)

  • 문제 (Problem): 레벨을 넘어갈 때 화면을 완전히 까맣게 덮는 로딩창(WBP_Loading) 연출이 필요함.
  • 오류 (Error): 로딩창 배경이 까맣게 덮였음에도 불구하고, 그 위에 메인 HUD의 체력바와 타이머가 그대로 겹쳐서 투과되어 보이는 현상 발생.
  • 원인 (Cause): 언리얼 엔진의 UMG 렌더링 순서를 결정하는 Z-Order 값이 메인 HUD와 로딩창 모두 기본값(0)으로 동일하게 설정되어 있어 렌더링 우선순위가 충돌함.
  • 해결 (Solution): 레벨 전환 시 로딩창을 띄우는 Add to Viewport 노드의 ZOrder 값을 100으로 대폭 상향시켜, 세상의 어떤 UI보다도 가장 앞쪽(최상단)에 렌더링되도록 강제하여 메인 UI를 완벽하게 가림.
