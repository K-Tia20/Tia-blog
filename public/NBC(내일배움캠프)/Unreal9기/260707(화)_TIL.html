💡 오늘 배운 점 (Today I Learned)

1. 블루프린트 변수 노출 (Instance Editable & Expose on Spawn)

  • 위젯이나 액터 안에서 직접 만든 변수에 **눈 모양 아이콘(Instance Editable)**을 켜두면, 외부 블루프린트나 에디터에서 해당 변수에 접근할 수 있는 ‘창구’가 열림을 배웠다.
  • 특히 Expose on Spawn을 체크하면, SpawnActor 노드로 해당 블루프린트를 소환할 때 입력 핀이 생겨 생성과 동시에 값을 쏙 집어넣어 줄 수 있다. (예: 데미지 텍스트 띄울 때 숫자 넘겨주기)

2. UI 최적화의 정석: Binding vs Event-Driven (Push)

  • 기존 방식 (Binding / Pull): UI 위젯 자체의 [Bind] 기능을 쓰거나 Event Tick을 쓰면, 매 프레임마다 UI가 게임 데이터를 검사하며 값을 퍼온다. 이는 연산 낭비가 심해 프레임 드랍(렉)의 주범이 된다.
  • 개선 방식 (Event Push): 무겁고 복잡한 연산은 **C++**가 전담하고, 체력 감소나 타이머 틱 등 **‘값이 변하는 딱 그 순간’**에만 C++에서 델리게이트(신호탄)를 쏜다. 블루프린트 UI는 평소엔 자고 있다가 신호가 올 때만 커스텀 이벤트를 실행해 화면의 숫자만 툭 바꾼다. (AAA급 게임 회사의 정석 최적화 구조!)

3. C++ ↔ Blueprint 데이터 연동 시 주의점

  • 프로그래머가 C++에서 CallFunctionByNameWithArguments 같은 코드로 블루프린트의 함수(이벤트)를 이름으로 직접 찾아 호출할 수 있다.
  • 이때 UI 디자이너는 프로그래머가 던져주는 **함수 이름, 입력 핀(Input)의 개수 및 데이터 타입(Float, Integer 등)**을 대소문자까지 완벽하게 똑같이 맞춰주어야 에러 없이 데이터가 꽂힌다는 것을 몸소 체험했다.

4. UMG 로딩창 애니메이션 (Fade 연출) 제작법

  • 위젯 안에서 전체 화면을 덮으려면 배경 이미지의 앵커(Anchor)를 ‘전체 화면 꽉 채우기’로 맞추고 Offset 4방향을 모두 0으로 주면 완벽하게 채워진다.
  • 하단 Animations 탭에서 타임라인을 만들고, 이미지와 텍스트의 Render Opacity (렌더링 투명도) 수치에 키프레임을 찍어주면(0.0 ↔ 1.0) 부드러운 암전(Fade Out) 및 밝아짐(Fade In) 연출을 뚝딱 만들 수 있다.

🛠️ Trouble Shooting (트러블슈팅)

1. UI 갱신 성능 저하 문제 (Binding 구조의 한계)

  • 문제 (Problem): 메인 화면(WBP_HUD)의 체력바, 웨이브 정보, 타이머가 실시간으로 갱신되어야 함.
  • 오류 (Error): 명시적인 크래시는 없으나, 기존 구조대로면 매 프레임마다 UI가 게임 데이터를 뒤져서 읽어오므로 몬스터가 많아질 시 심각한 프레임 드랍(렉)이 발생할 우려가 큼.
  • 원인 (Cause): 언리얼 UMG의 기본 [Bind] 기능(Pull 방식)을 사용했기 때문. 이 방식은 UI가 변화 여부와 상관없이 매 틱(Tick)마다 데이터를 능동적으로 퍼가기 때문에 연산 비용이 매우 높음.
  • 해결 (Solution): 기존 위젯의 바인딩을 모두 해제(Remove)하고 Event-Driven(Push) 방식으로 구조를 전면 개편함. UI 측에는 값을 받을 수 있는 ‘커스텀 이벤트’만 열어두고, C++ 로직에서 값이 변경되는 그 찰나의 순간에만 신호(Delegate)를 쏘아 UI를 수동으로 1번씩만 갱신하게 만들어 최적화를 달성함.

2. C++ ↔ Blueprint 간 이벤트 파라미터 불일치

  • 문제 (Problem): C++에서 이벤트 신호를 쐈음에도 불구하고 블루프린트 UI(WBP_HUD) 측에서 데이터를 정상적으로 받아오지 못하거나 에러가 날 위험 감지.
  • 오류 (Error): 블루프린트 커스텀 이벤트 노드(UpdatePlayerHP 등)에 데이터를 입력받을 핀(Input)이 뚫려있지 않거나, 핀 개수 및 데이터 타입이 불일치함.
  • 원인 (Cause): 프로그래머가 C++에서 CallFunctionByNameWithArguments 방식을 통해 정해진 형식(예: Float 2개, Int 3개 등)을 문자열로 강제 호출하고 있었으나, UI 이벤트 그래프에서는 외부 입력을 받지 않고 내부 변수를 쓰도록 잘못 연결되어 있었음.
  • 해결 (Solution): 블루프린트 내부에 띄워져 있던 독립 변수들을 삭제하고, 빨간색 커스텀 이벤트 노드 자체의 디테일 패널 ➡️ Inputs에서 프로그래머가 보낸 C++ 변수명(Health, MaxHealth, CurrentWave 등)과 데이터 타입(Float, Int)을 완벽하게 동일하게 세팅하여 데이터가 정상적으로 수신되도록 수정함.

3. 타이머 UI 멈춤 (C++ 백엔드 로직 버그)

  • 문제 (Problem): UI 타이머 연동 및 포맷(Time Seconds to String) 세팅을 완벽하게 끝냈음에도, 게임 플레이 시 시간이 전혀 흘러가지 않음.
  • 오류 (Error): 게임 시작 후 0.1초가 지난 뒤 타이머 로직이 완전히 멈춰버리고 UI로 갱신 이벤트가 날아오지 않음.
  • 원인 (Cause): 블루프린트 문제가 아닌 C++ 코드 버그였음. PFGameMode.cpp에서 SetTimer를 호출할 때 루프(bLoop) 인자를 false로 잘못 설정했고, 시간이 깎인 직후 PFGameState->UpdateHUD();를 호출하는 트리거 로직을 빼먹어 UI로 신호가 전달되지 않았음.
  • 해결 (Solution): 프로그래머 담당자에게 C++ 코드 PFGameMode.cpp의 해당 라인을 찾아 원인을 리포팅함. 루프 인자를 true로 고치고 타이머 함수 내부에 UpdateHUD();를 1줄 추가하도록 코드 리뷰(피드백)를 진행하여 해결함.
